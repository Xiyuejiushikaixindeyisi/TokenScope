# 监控输入、计量与证据约定

版本：v0.2.2-discussion，2026-10-26。维护：Token 监控；消费者：前缀分析、长度分析、前端展示、后续 Agent。已确认事项与建议字段分开；本文件尚非正式 API/JSON Schema。前版 [v0.1](MONITORING_V0_1.md) 仅供追溯。

## 已确认范围

- 每模型一个用户提供的带表头 CSV；Qwen3.6-27B、DeepSeek-V4-Flash-0731、GLM-5.2。
- `request_input` 是 GF 转换后送往推理服务的完整原始 OpenAI v1 JSON 请求体。模型输入均为纯文本，包含工具定义、工具调用和文本工具返回。流式是响应方式，不改变输入计量范围。
- 模板前统计 CSV 正常解码后的 JSON 原字符串，包括键、标点、空白、参数；不能重新序列化，CSV 容器自身的引号/转义不计入。
- 模板后按模型真实模板/专用编码器及模式转换，不将整个 JSON 包成 user 消息。
- 每 CSV 空缓存开始，appid × 模型独立，HBM 无限；前一请求可缓存输入立即对后一请求可用。仅模拟可见输入，输出 Token 数单独统计。
- page 分配和复用以对应 Ascend 代码/PR 为主要依据；公式和模型名称不能替代部署/规则身份。
- 后端提供总量、命中率和分位数的权威值；前端绘图和交互。页面访问不启动计算。
- 全量轻量证据、按需详细映射；两类诊断调用监控维护的编码/计量能力。
- 状态缓存主结果采用固定、可配置的顺序 prefill 规则；每个合法边界都保存状态的方案单列理论情景。固定规则不是现场真实调度的声明，具体预算尚待确定。

## 输入

| CSV 列 | 含义 |
| --- | --- |
| hash_id | 请求唯一标识；重复数据处理政策待定 |
| appid | 请求租户 |
| model_handle_start_time | 模型处理开始时间；格式/时区待确认 |
| completion_tokens | 输出长度，来自 CSV，不由监控重编码 |
| request_input | 上述 GF 后、模板前的原始 JSON 字符串 |

运行清单建议额外绑定 CSV SHA256、模型 revision、tokenizer/模板文件摘要及有效模式、缓存 profile、窗口和时区；这些不强制新增为用户 CSV 的列。缺失或失败不能静默填 0，规则未知不能伪装成已校准命中率。

## 计量语义草案

| 概念名 | 语义 |
| --- | --- |
| json_tokens / J | 对应模型 tokenizer 编码原始 JSON 的长度，不注入模板或额外 BOS/EOS |
| prompt_tokens / P | 实际模板/专用编码产生的输入 Token IDs 长度 |
| ideal_cached_input_tokens / H | 所选缓存 profile 下可以复用的输入前缀 Token 数 |
| ideal_compute_input_tokens / C | P-H；假定理想命中即真实命中时的输入重算估计 |
| completion_tokens | CSV 的输出 Token 数，与 C 分开 |
| ideal_hit_rate | 建议 sum(H)/sum(P)，不是请求百分比平均值；分母 0 时不可计算 |
| json_to_prompt_token_delta | P-J，可为负；不是“纯模板开销” |

加权公式尚待确认。J/P/H/C 总量与对应请求数必须说明有效集合；编码成功但缓存 profile 未核实时，J/P 可用而 H/C unavailable，各分母/质量计数须显式给出，不能声称用了同一完整集合。

三组分布分别取 J/P/C，每组独立降序，一请求一点，点关联请求身份。后端提供各组 P50/P80/P90；分位数定义不因降序图而反转。建议线性 type 7，算法仍待确认。后端可分页提供完整排序序列；展示端不重新定义权威分位数。

## 模块之间的最小信息草案

| 记录 | 必要内容 |
| --- | --- |
| EncodingRecord | 请求定位与 hash_id/appid/时间、模型/编码身份、J/P、供仿真的 prompt IDs、轻量证据、质量状态 |
| CacheReplayRecord | 请求定位、cache_profile_id、H/C、共同恢复边界、必要的组级候选边界/限制条件、检查点事件 |
| MonitoringResult | 运行/窗口/来源/版本身份、质量统计、指标汇总、分位数及排序点数据位置、报警信号 |
| EncodingExplanation | 对指定请求和编码身份生成的来源→文本 byte span→Token 映射、完整性状态、与全量 IDs 摘要的一致性结果 |

这些是逻辑记录，尚未冻结语言类型、存储格式、RPC 或 CLI。诊断可以读结果或调用共用实现，不维护第二套 tokenizer 或命中算法。

## 缓存规则身份草案

`cache_profile` 区分来源版本/补丁、单实例/P/D 等角色、prefix cache 开关、物理 page 大小/布局、slot→原始 Token 换算、压缩率/CP、hash/match unit、状态 admission/retention、跨组恢复边界和 MTP 读写回退。只标一个 block_size 不足以比较结果。

需要区分经核对规则、明确简化的情景、未核实规则；不同类别的结果不能混入同一监控基线。若实际 prefix cache 关闭，则当前配置的 H=0 与假设开启后的潜在复用是两个不同问题，不能隐式切换。

物理页数不直接用来计算 H；必须换算为原始输入 Token 并满足所有参与组可恢复条件。H 不包含 padding。无限容量不意味未保存状态自动存在。真实传输时延、生成 Token 缓存、稀疏 top-k 选择不由本 CSV 推断。

v0.2.1 补充建议：每组明确记录原始 B 的单位、规范化的存储条目数和原始 Token 覆盖量，以及参与恢复所需的 component/state。规则解析与请求回放分开；结果中的 H 必须是所有必要组共同合法的恢复边界，不能仅取各组最大长度的最小值后假定可以截短状态。请求先查询已有缓存，再发布本请求物化的缓存，避免把新写状态倒算为已命中。物理 group 数量和页布局不写成模型品牌常量。

v0.2.2 补充：主结果是指定调度/保存策略下的无限容量复用结果，不是跨所有保存策略的全局最大值。`prefill_policy` 建议包含每步 Token 预算、拆分算法版本及状态发布规则，并参与 profile 身份。与 CSV batch、Rust 编码分块分别配置；不得用数据处理并行度改变仿真语义。

请求回放顺序约定为：查已有键/状态 → 按版本规则确定 H/C → 从 H 规划剩余 prefill → 逐步发布允许保存的内容 → 完成本请求后供下一请求使用。已发布的有效缓存不会仅因请求结束而在无限容量情景下被删除；显式失效或不可恢复状态仍须处理。生成 Token IDs 未提供，不由输出计数补造缓存。

建议每请求保留简明组级边界/所需状态是否存在、检查点发布摘要及可重放轨迹引用；详细步骤可按同一 profile 再生成。主结果与理论保存情景分别标识、分开统计和基线；后者的合法边界或数值状态能力未核实则 unavailable，不伪造结果。

## 编码证据与按需细查

全量轻量层保留：
- 原始文件/行定位及摘要；原输入可重放。
- 编码资产/模式身份、J/P 和模板后 IDs 摘要。
- 经验证模板适配器给出的特殊 token 区间，以及其来源标记；区间统一声明为 UTF-8 byte、左闭右开。
- 映射能力/完整性状态；未获取的字段保持 unavailable，不能搜索字符串后假装知道来源。

详细层从固定输入和同一编码配置生成，并与全量 prompt IDs 摘要校验。Recipe 快路径不计算 offsets；详细路径可用带 offsets 的等价接口，不允许改变模板/特殊 token 处理。此调用是分析工作流显式操作，不由页面访问隐式触发。

原始 JSON 与模型输入分别建账。跨来源边界的 token 单列 mixed-boundary，未映射 token 单列 unknown；独占计数桶之和分别等于 J/P，重叠来源链接另存，防止重复加和。字段删除、格式转换、模板插入等是转换事实；异常判定和建议由长度分析任务设计。详细映射不是全量两小时计算的必经环节，其自身预算后续约定。

## 告警边界（待收敛）

建议事件表达运行/窗口、appid/模型、指标值与比较方向、阈值/基线/规则版本、数据质量、结果位置、路由目标及去重身份。低命中和长度异常分别供对应分析任务消费；总量/请求数上升的路由待讨论。无效或不兼容 profile 不静默触发正常业务诊断。

阈值、基线、最小样本、去重/重试、防抖及自动触发准入尚未冻结。监控不设计分析器内部逻辑，样例事件不实际派发。
