## 1. 用户目标与产品结构

用户在一个appid的请求数据中，找出自己能改的prompt/编排内容，看到证据、具体改法及修改后的输入计量变化。

产品分两个独立页签，共享同一数据范围和评估能力：

| 页签 | 回答的问题 | 首期探测器 |
| --- | --- | --- |
| 低命中率分析 | 哪些可修改的输入差异破坏了稳定前缀？ | L1动态元数据、L2工具排列、L3工具定义/集合漂移、L4历史改写、L5序列化不确定 |
| Token内容分析 | 哪些内容占据输入、重复搬运或超出内容约定？ | T1工具定义负担、T2大工具返回、T3重复搬运、T4历史工具结果负担 |

[低命中规则](LOW_HIT_DETECTORS.md)和[Token内容规则](TOKEN_CONTENT_DETECTORS.md)逐项列出公开依据、现有数据可判定范围、具体规则、修改建议与离线评估方式。公开实践是设计依据；现场问题和收益必须用当前appid证据证明。PrefixLens仅为参考，不是规则来源或运行依赖。

## 2. 输入与已有能力

范围为目标appid × 模型服务/编码身份 × 明确窗口。默认取已完成监控运行中该appid的有效请求；同appid不同模型服务/编码身份不混算，缺服务绑定保留原模型身份。只回放这个范围，不要求其他appid或整个生命周期历史。

| 已有或已核对的数据能力 | 首期用途 | 限制 |
| --- | --- | --- |
| 请求原文、请求来源键、appid、模型、时间/原记录顺序 | 结构解析、定位、窗口与对照 | appid不是agent/session；顺序不等于执行链 |
| 统一J/P/H/C及源O计数 | 基线与修改前后输入评估 | O没有对应完整响应正文，不做输出内容诊断 |
| 输入IDs及编码/模板/配置身份 | 输入差异、同条件编码与前缀比较 | 资产不可复用时只保留可读内容事实，评估阻断 |
| 字符串字段Pointer/字符/字节/摘要 | 内容定位和来源大小 | 不等于精确字段Token归属，结构容器需分析阶段聚合 |
| 详细编码证据、原缓存事件（按可用性） | 输入位置核验、原指标解释 | 模板参与/映射不足则显式未知；对照请求不是已记录缓存来源 |

能力事实以[现场交接](../../huawei/MONITORING_V1_ACCEPTANCE_20261030.md)、[实际API](../../contracts/MONITORING_IMPLEMENTED_API.md)和原运行身份为准；上述可用数据不表示探测器已经实现。分析器复用统一编码与缓存计量，不能另写一套算法。

## 3. 业务结论与行动

每张卡片先说明观察事实，再说明可得结论：

- 已识别输入构造问题：例如已知误注入cch、同集合工具随机排列。
- 优化机会：例如工具返回占用大、同一载荷重复出现，但尚无证据认定无用。
- 超出业务约定：只有明确预算/保留策略且可按同单位验证时使用。
- 需补证据：例如历史部分不同但缺可靠请求关联。

独立显示修改与评估状态。事实成立不代表收益已验证；“已评估”也不保证改善。已知误注入cch清理按业务信息无损处理，同集合/定义固定排序是稳定化修复；内容裁剪单列其保留规则与任务信息影响。

模型配置/模板身份校验在后台完成，不作为业务异常卡片，不要求用户修改模型配置。规则细节可展开查看；没有统一的90%命中率或固定Token异常阈值。

## 4. 主流程与离线评估

用户选择appid/服务/窗口，显式发起分析 → 后台读取和校验 → 分别产生两个方向的发现 → 展示证据与修改方案 → 显式评估所选方案 → 保存并展示结果。页面访问只读保存结果。

探测器无固定行业优先级；按适用性收集观察，不能首个命中即停止。共享核验结果，不用前一个探测器的修改副本继续归因。执行成本与预算待实现测量，报告须公开实际覆盖。

离线评估对目标appid窗口构造原始基线和修改副本，用同一编码资产、顺序、缓存规则和起点重放。既可单项，也可已明确的组合方案；组合必须实际评估，不相加单项收益。只改原结构，不直接改Token IDs制造改善。详见[流程与评估](PHASE1_PLAN.md)。

结果同时显示P（输入Token）、H（理想命中Token）、C（理想重算Token）、R=ΣH/ΣP。P下降、R下降、C上升可以同时出现，必须原样呈现。只评价静态输入，不能据此预测未来输出、调用数、质量、真实费用或TTFT。

## 5. 业务展示

首页给应用/服务/窗口、有效请求、两方向覆盖及当前指标；下面为两个独立页签：

- 低命中页：问题位置 → 对照差异 → 稳定前缀影响 → 修复动作 → 离线改善。
- Token内容页：内容来源与大小 → 重复/预算/保留策略事实 → 保留或替换规则 → 离线变化。

详情展示具体请求、字段路径、脱敏片段、依据、异常判据、修改前后差异、评估范围及未完成原因。不同卡片可共用证据/方案，请求总数取并集；不汇总重叠收益。
