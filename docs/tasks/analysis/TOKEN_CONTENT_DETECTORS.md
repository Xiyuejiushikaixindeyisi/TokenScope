# 首期Token内容分析：探测器与判定规则

> 当前分工：主会话继续低命中后端，Token异常后端已获准fork并启动；见[分线交接](BACKEND_SPLIT_HANDOFF.md)。下文“本轮未编码”为产品形成阶段事实；本次仅交接整理，尚未修改源码。逻辑字段尚非冻结API。

v0.4产品基线，2026-10-31已获用户审批。首期只分析已有模型请求中的内容；不检测实际执行Loop、不推断未来输出。编号用于引用，不设固定执行优先级。共用范围和评估见[流程](PHASE1_PLAN.md)，示例见[展示](DISPLAY_EXAMPLES.md)。

## 共用判定与计量

研究依据证明内容负担的机制；下列判据是本项目产品提案，尚未在现场样本验证。正常内容大、历史重复携带和高Token输入本身都不是故障。

- 每个适用请求先给组成事实，再判断是否有具体优化机会；只有违反已提供的业务限制或明确构造约定，才使用“超限/异常”措辞。业务限制的值、单位、来源和版本必须随发现保存。
- 当前原文字段可计算解码后字符串字符数和UTF-8字节数、结构项数、内容相等性；tools为结构对象时，定义大小使用明确的展示序列化规则并标注，不冒充原始JSON字节或Token。
- 请求P来自统一编码。已有source_fields不保证精确字段Token映射；只有可靠映射才展示模型输入Token区间及不重叠并集占比。没有映射就给字节/结构事实＋请求P，不显示伪精确Token饼图。
- 删除字段后的ΔP是修改效果，不是该字段原始Token贡献。原JSON token数J也不是模型实际输入P。
- 不发明“超过8K/30%就是异常”的行业阈值。未提供业务上限时，对完整扫描结果按可比单位降序展示，并标“内容负担排行”；折叠/Top-K只控制展示。设定筛选上限/预算时显式保存，不改变异常定义。
- 同请求重复只计算不重叠载荷；跨请求正常重发历史按每次实际P计量，但不作为重复注入错误，也不当作多次工具执行。

## T1 工具定义负担

**依据。** [Anthropic高级工具使用](https://www.anthropic.com/research/advanced-tool-use)展示大量MCP工具定义挤占上下文，讨论按需发现与延迟加载。支持“检查工具定义负担”，不支持“没看到调用就删工具”。

**现有数据能判定。** tools的数量、各定义/描述/Schema大小、重复说明、实际模板参与情况。没有完整执行事件与任务需求，不能断言某工具无用。

**具体规则。**

1. 逐请求枚举完整tools，按唯一身份定位；列出各定义及description、parameters/schema的大小，父容器与子字段不重复相加。
2. 确认哪些内容被模板消费。若无法精确映射，展示“原结构大小，Token占比未知”；被模板忽略的定义不计模型输入负担。
3. 若有业务定义预算，按同单位比较：已消费内容度量超过预算才报“工具定义超限”；无预算仅给负担排行。
4. 重复定义文本需给出具体相同片段与位置；相似工具名不能证明冗余，不自动合并不同权限/语义的工具。

**修改建议。** 精简明确重复的工具说明；保留参数含义、必填约束及必要示例。大量工具的长期方案可建议稳定入口和按需加载，但不把每轮任意删加工具清单当修复。

**离线评估。** 可评估业务指定的description替换/冗余说明删除，保存确切文本、路径和结构校验，不删除必填Schema来制造收益。需要动态搜索/延迟加载的架构方案本期仅建议；不以“离线删除未调用工具”冒充真实改造。可执行副本按同appid窗口比较P/C及R；精简前部定义的缓存影响同样展示。

**业务表述。** “工具定义内容负担集中在3项说明，可检查精简”，而非“发现3个无用工具”。

## T2 大工具返回直接注入

**依据。** [Anthropic MCP代码执行](https://www.anthropic.com/research/code-execution-with-mcp)讨论大表格、文档等直接进入模型，以及执行侧过滤、聚合后返回必要内容。

**现有数据能判定。** 请求历史中的tool返回、其关联调用信息（若正文携带）、条目/行数、字符串大小和模板参与。数据表示的是请求里的历史内容，不是当前工具响应事件；不能保证截断前原始大小或实际执行次数。

**具体规则。**

1. 按原协议解析tool结果块，保留调用ID及结果结构；普通用户粘贴内容不能冒充tool返回。
2. 按内容形式统计JSON数组条目、文本行数/字节等。只统计已观测内容；无法解析时退为文本大小，不臆测数据类型。
3. 若与明确返回契约比较：例如已提供的最大条目数或允许字段集合，超限/多余字段可判“返回注入超出约定”；没有契约只称“大工具返回，待选择保留规则”。
4. 确认内容进入模型。仅原文大但被模板忽略，不报模型Token负担。

**修改建议。** 在工具执行侧过滤目标行/列、限制日志范围、分页或只返回统计摘要；保留继续读取方式。业务需要全文时不建议盲目截断。

**离线评估。** 首期可做确定性保留字段、保留指定条目/行范围；必须明确规则参数和截断标记，保留tool调用配对和结果容器。无业务保留规则可提供显式假设方案，标“内容裁剪、任务效果未验证”；不默认无损。不能离线凭空生成摘要或分页执行流程。若同一历史结果在多个快照中出现，按已选位置/摘要规则逐个修改并记录覆盖，不宣称已还原完整会话。

**业务表述。** “某返回在当前请求携带10,000行，可评估只保留指定列”，不写“工具执行了10,000次”。

## T3 同一大载荷重复搬运

**依据。** [Anthropic MCP代码执行](https://www.anthropic.com/research/code-execution-with-mcp)给出从工具取回整份文档、再转传到另一工具参数的重复模型处理案例。

**现有数据能判定。** 同一请求中，工具返回与历史工具调用参数/消息正文是否含完全相同载荷，所在字段和重叠范围。不能仅凭相同文本证明某次复制没有业务必要。

**具体规则。**

1. 比较同一请求的不同业务位置，至少两处相同非空载荷；首期采用解码后完全相同字符串或明确定义的结构相等，不以语义相似直接判重复。
2. 首先识别完整结构字段载荷，例如tool返回content与另一个调用arguments中的document；碎片substring只作为证据候选，必须显示确切区间，不能用短词/工具ID/协议字段重复报搬运问题。
3. 仅保留包含至少一处工具载荷的业务内容关系；排除同一位置的父子容器重复计数、嵌套匹配重叠及正常协议引用。按重复内容大小排行，不以排行自动断言错误。
4. 重复出现k次可展示(k−1)份“重复出现的字节”，这是内容事实，不是可删除Token、可节约C或执行次数。是否冗余需业务传递约定；必要示例/引用保留。

**修改建议。** 如下游工具支持文件路径/对象引用，使用引用传递；或在执行环境内直接转传，只向模型返回必要状态。不得把原本要求正文的工具参数随意换成文件名。

**离线评估。** 已有工具协议支持引用，且具体引用在业务中可解析时，可替换准确载荷为该引用并重放；只表示这份修改后的静态输入效果。没有引用能力时仅给建议，不填收益。若业务明确允许删掉额外复制的普通消息，才评估去掉该副本；必需tool结果/调用参数不直接清空。与T2同位置裁剪存在交叉时共用证据，组合另评估。

**业务表述。** “相同文档在一个请求中出现两处，第二处为传给另一工具的参数；是否可改引用取决于工具协议”，不写“重复工具调用/Loop”。

## T4 历史工具结果内容负担

**依据。** [Anthropic上下文管理](https://claude.com/blog/context-management)通过清理旧工具结果控制上下文；[Manus](https://www.manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)同时强调稳定历史前缀。两者说明清理与缓存存在取舍，不意味着所有旧结果都该删除。

**现有数据能判定。** 单个请求内保留了多少历史tool结果、各自大小、消息位置。没有可靠链路与任务状态，不能判“持续增长”“过期”或“任务不再需要”。

**具体规则。**

1. 枚举请求消息中tool结果及其索引/调用ID，展示大小与后续消息数；消息索引不等于真实turn或时长。
2. 默认只给“历史工具结果负担”清单。跨请求出现相同历史结果属于正常追加，不触发T3。
3. 只有已提供内容保留策略时，例如保留最近K个结果块、某类载荷在明确位置前只留摘要/引用，才判断当前快照是否超出策略。K及策略来自业务，不能编造通用默认。
4. “结果已经过期/任务无进展”等过程结论本期不产生；即使大小超限也仅判违反内容保留规则。

**修改建议。** 按明确策略保留近期结果和必要摘要/引用，维护按需重读能力；保留工具调用结构和所需历史。不能让减少P成为破坏任务信息的默认目标。

**离线评估。** 有具体保留策略与合法替代内容时，在每条选定请求快照上应用同一规则，保留配对及协议结构，统一重放。只比较该窗口静态P/C/H/R，不重新运行agent。清理会改变旧前缀，可能P下降而C上升，必须如实展示。缺策略时显示“未评估：未指定历史结果保留规则”，不额外等待完整trace来做已有内容清单。

## 首期输出边界

T1–T4各自输出内容位置、度量单位、模板参与状态、判定条件和动作建议。来源不足或无法判断必要性时，保留优化机会状态；不能用高P或人工置信度包装成确定异常。

T2与T4常指向同一历史tool结果，T3可能覆盖其复制项。卡片可有不同解释，但关联同一证据/修改方案；请求数、重复字节和离线收益均不得跨卡片直接相加。Loop与执行重试不属于本表探测器，仍仅列[补充数据需求](PHASE1_PLAN.md)。
