## 1. 验证层次

| 层次 | 检查目标 | 通过证据 |
| --- | --- | --- |
| 纯解析/规则 | 协议路径、内容度量、判据、正常行为排除 | 明确输入和独立预期的单元测试 |
| 变换 | 原值保护、内外层JSON、结构保持、失败原子性 | 变更manifest与未改字段断言 |
| 真实统一编码 | 修改后可编码，批量/详细身份及P一致 | 三种已支持模型资产下的小型fixture与身份记录 |
| 公共评估接入 | appid/窗口隔离、原/子窗口基线、负收益及失败状态 | 真实公共评估运行结果；假服务不替代此层 |
| 报告消费 | 证据/状态/计数去重与只读查询 | 后端接口结果与资源行为；不代替前端视觉验收 |

只测T1–T4及直接接入，不重复穷举监控缓存算法。实际测试选择随最终改动范围落实。

## 4. 规模、恢复与只读

- 流式处理多请求、极大单请求及许多重复单元，测实际内存/耗时并记录输入规模；确定资源预算默认值，预算与业务阈值分离。
- 预算停止保留partial和停止位置；不得截断正文继续宣称全量。
- 同源/参数/版本/预算重复执行应产生稳定事实顺序与摘要。
- GET报告/证据不能调用编码、探测、工具或回放；读取次数不改变结果。
- source_record_index不同但hash_id相同，必须保留不同请求。
- 同一证据跨T2/T4、同请求多观察，报告涉及数按请求并集；短片段/脱敏展示不影响计算。
- 取消、源读取失败、公共评估失败应关闭迭代资源，保留已存事实或失败状态；重试按公共不可变任务规则，原证据不得改写。
