## 2. TA000：接口及验证基线

draft-2增量：记录reason_codes/reason_note、两个enable开关、direction_status/stage_status的正式类型；明确Token gate不适用及直接full评估的wire表示。核对公共第9.2节接纳记录即可，不重新申请三项方向审批；仍需固定元数据编码样例、完整原文/修改副本读取引用和registry实际版本。

必须记录：源码HEAD及直接依赖摘要、公共契约版本/摘要与确认状态、Token Descriptor/规则/解析器/度量/操作版本、模型资产/原profile身份、测试fixture来源和预期。

接口签收需覆盖：完整原文与capture_truncation分离；外层/内层定位；原值guard；位置/单元/观察身份；返回fragment和变换处理器注册；失败/partial/取消映射。未确认项标pending，不靠mock跑通当作签收。

fixture采用小型人工构造，可放Git；真实正文与生成产物遵守项目存储约定。数值预期人工或独立方法计算，不能用被测解析函数生成预期再验证自身。现有源码不具备的精确Token归属用unknown验证，不新增映射工程。

## 3. TA001–TA003：内容规则验收

所有规则必须同时覆盖正例、反例、数据不足和预算停止；“没有发现”“没有检查”“已检查但未知”分别表达。

- 同原文/版本/策略/预算重复执行，位置id、unit_id、观察及顺序一致；相同hash_id不同source_record_index保留两条。
- 字符/UTF-8/结构展示字节/条目/行数单位严格分离；父子与T2/T4共享不累加；值为空按适用规则处理，不伪造异常。
- T1保留定义语义；T2仅tool内容，用户粘贴JSON不冒充工具；T4结果容器与content part的K口径明确。
- T3仅同请求，至少一处工具载荷，完整相等而非语义猜测；数值大整数、true/1、1/1.0、key顺序/字符串表示变化按固定比较方法给出结果。
- 没有业务限额/保留规则只输出事实或机会；actual等于limit不误报大于；模板参与未知不生成Token占比。

这些验收不需要推理模型生成，也不要求完整session/trace。批次结果中分别统计各规则checked/unknown/partial，不发明现场检出率。

## 4. TA004：修改正确性与真实编码

接受每类已批准内容变换的小型fixture：description替换、字段/条目/行投影、内嵌arguments引用替换、历史结果合法替换、明确授权普通消息删除。

成功条件：全target guards通过；不允许修改的name/Schema/role/call_id/非目标载荷保持；数组剩余元素值与次序正确；内层未改数值词法保留；原文/源库/原Token切片摘要不变。原始字符串有格式差异时manifest如实单列。

失败条件必须测试：原值变化、目标缺失、重复key、引用协议缺失、删必需调用结构、冲突操作、非目标数值变化。任一目标失败则计划阻断；不能跳过失败目标形成“成功后”的收益。

用项目实际三模型资产和原profile检验统一编码：批量/详细IDs与P一致、特殊Token字面值处理不绕过原实现。若本地资产不可用，记录blocked而不是测试通过；不下载/更换资产来偷偷改变验证身份。此层证明修改副本可编码，不证明任务效果或节省O。

## 5. TA005：公共真实接入与评估

本批新增必须通过的D2-01–D2-08见[TESTS](TESTS.md)：人工原因路由、低命中pilot/full完成后才启动Token、方向级失败可继续/共享失败阻断、原始scope隔离、Token不套>1pp门槛、完整证据读取、无参数不自动裁剪、跨方向组合冲突。上述不以mock代替真实公共任务。TA002/TA003同时验证原有四规则不新增前序对照/会话依赖。

必须经实际公共服务完成显式分析→保存报告→选择方案→显式评估→读取结果。单元假服务仅验证插件边界，不能关闭此批。

- 另一个appid使用相同前缀不影响目标范围；两个源run不隐式拼接。每个逐请求结果可回溯到RequestKey与源摘要。
- 原运行完整窗口核对原IDs/P/H/C；子窗口前后从同一空账本开始，源H/C单独展示；修改子集与全窗口指标分别存在。
- 验证P下降但C上升、零效果、组合交叉影响；组合必须真正回放，不能加单项；after O/费用/质量为空或不支持。
- 全范围的每条请求参与回放，目标失败不丢行，失败无after/收益；读取封存源前后SHA一致。
- T2/T4两张发现共用一个unit、一个涉及请求；跨方向共同location可关联，规则观察仍独立。相同操作候选合并refs，冲突方案受阻。
- GET报告/证据不调用解析、编码、回放或工具；跨报告证据引用拒绝；重复提交与重试遵循公共幂等/attempt协议。

公共方维护任务/HTTP/数据库实现；本线提供fixture、期望与本线结果证据。双方实际接入版本和结果分别登记，不以一方文档代签另一方完成。

## 6. TA006：规模、取消、回归及交接

本批新增退出要求：记录等待阶段与实际Token执行耗时，防止将低命中评估等待计成Token探测性能；验证中断后不误启动Token、重试不重复归组；交接Token未开始/受阻/内容事实/未评估/零负结果样例。后端只读GET和前端展示验收仍分开，未完成前端不能被写成已通过。

资源测量使用明确规模梯度：同单请求大小下增加请求数，以及固定请求数下增加单请求字节/单元数/重复候选。记录wall time、峰值RSS、输入与检查规模、模型身份和机器配置；检查无整个appid原文常驻内存、无全字段二次方比较回退。参数值在校准后写固定配置并复测，不以未经实测的延迟数字作承诺。

执行预算验收必须有刚低于/等于/超过限制三组，并验证partial与停止位置；显示片段限长不得改变完整计算。预算默认值与业务异常阈值分开，不能为了全通过放宽既定预算或隐藏未查请求。

取消在公共RunControl规定边界生效，解析内调用不可抢占的限制写入结果；显式retry产生新attempt，原证据/结果不变。崩溃、封存/发布失败等公共故障由公共维护方验证，本线联合检查观察不会重复累计、失败不会伪装成功。

回归按实际触及模块选择：新增Token单元/接入；统一编码接口调用；公共GET只读/worker注册；已有用户/MA监控必要兼容。没有修改监控算法时不重复写整套缓存算法测试。最终必要检查全部通过后不无故重复测试。

交接至少包含IMPLEMENTED_API或公共契约引用、实际CODEMAP、源码身份、用例/命令/结果、固定预算、样例报告/评估身份及限制。真实现场数据、前端视觉、容器和部署状态分别列出；本地通过不能代替现场验收。

## 7. 批次结果与回退标准

实施时每批维护batches/TAxxx/RESULT.md，包含状态、修改文件/公共编辑方、依赖身份、执行命令与结果、失败及修复、偏差、未完成、回退方式。当前不预建“通过”结果文件。

阻断交付的问题：错appid/窗口、源污染、伪精确Token、漏guard、失败丢行、重复计量、GET触发分析、无策略报异常、unknown写成正常、用mock冒充真实接入。修复后重跑直接受影响检查。

回退优先禁用本线规则/插件注册并回到上一可用版本，保持公共历史报告可读；不删除源监控运行、不反向改写原文、不降低契约版本掩盖问题。若变更影响公共Schema，迁移/回退由公共维护方明确登记后执行。

完成口径：TA000–TA006实现及必需本地验证闭环才称Token后端代码完成；技术设计完成、纯规则测试、真实公共接入、现场通过分别记录。参数错配调研结论不作为本计划额外验收门槛。
