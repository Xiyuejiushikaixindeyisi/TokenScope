## 4. 宣传与V3的交接原则

当前优先做清晰的产品宣传，继续现有V3 session里已开展的听众/大纲讨论，**先明确服务谁、帮助做什么判断、真实业务得到什么证据，再讨论细化/重构，避免为了扩功能而扩功能**。本会话不接管宣传设计或生成未经讨论的PPT。

宣传可以据证说明：CPU方式读取已有请求数据、用户/模型请求画像与理想复用分析、参数化TTFT参考、MA指标及缺数解释、已产出的请求差异证据。当前不应说：所有八类探测器都在本次现场产生了有效建议、Token建议覆盖所有业务、搜索已无障碍覆盖所有模型、已验证自动根因/自动调优/真实吞吐保证、32GiB稳定承载任意规模、所有模型全量30分钟。前期PrefixLens案例与当前V2验证分开；“CPU无需推理卡”不等于低内存或固定耗时。

V3需要以公司真实业务为起点做appid×模型×任务/模板族的调查：业务在做什么（如实体提取、分类、文本整理、对话、工具链）、请求/输出长度和分布、到达/并发、tools/messages、固定与动态内容、语义不可删改约束、可用标签及业务负责人确认。保留混合/未知、小样本与数据缺失；不按模型品牌或工具有无直接贴场景标签。外部技术报告用来解释机制/提供候选，不替代本公司数据与业务确认。

性能研究应把32GiB有效预算、长尾单条/总量、任务阶段峰值、API健康、队列公平、小任务被大任务阻塞、取消与恢复、磁盘/持久化纳入设计与验收。流式/分块/磁盘索引、减少重复解析编码、任务准入/资源预算、恢复点是可评估方向，不在本轮确定实现或调整mem_limit；单纯加内存不能替代产品能力和成本设计。详见[V3输入交接](../product-v3/HV2_EVIDENCE_HANDOFF_20261105.md)。
