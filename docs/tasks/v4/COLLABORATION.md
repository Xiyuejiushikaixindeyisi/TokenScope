# V4本机、华为与人机协作

## 身份与职责

- 用户：产品定位/汇报受众与表达、前端DEMO、业务语义/改法风险、模型目标及TTFT参数、现场停机和最终验收的决定者。
- V4产品设计与汇报：负责需求、叙事/材料、最小页面差异DEMO和需求一致性验收；不改产品代码、不代开发测试、不持续调度未授权工作。
- V4模型演进与开发：独立审查方案、核资产复用、稳定公共身份和后端契约；获准后统一实现和测试必要前后端改动，避免多人双写。
- 镜像打包与审查（既有会话）：跨版本交付审查、Git/版本/文档、获授权独立E2E/构建/镜像代码包/现场执行说明。不自行产品编码或更改展示方案。
- 华为agent：现场只读取证、用户授权后的部署/真实验证，最终单Markdown回传；不擅自改产品或以现场方便为由降低测试门槛。

两个V4角色实际ID均未知，待用户新会话启动登记；两个V3角色已休眠，历史ID不转给V4。启动prompt是交接材料，本轮没有发送或创建会话。人负责最终批准；会话内授权工作自行推进，不每一步重复询问。

## 工作顺序与交付物

1. 产品先用现有报告形成可讨论汇报稿和必要DEMO；开发可并行只读盘点资产。两者不依赖全量现场重跑。
2. 与用户确认目标和详细范围；涉及前端修改必须先展示DEMO，取得“前端展示审批通过”，再实施该页面。不以旧HTML批准替代本次变更批准，不强迫用户重复批准已批准同一稿。
3. 后端/公共模型身份先验证并冻结，明确兼容旧API/结果；前端依冻结契约接入。开发技术方案可质疑产品方案的实现选择，但不能自行扩大功能或更改已批展示。
4. 获准开发后在项目本机源码/WSL环境实现，先针对性测试再E2E。每次新候选E2E先核停本项目旧服务、释放端口，独立state/浏览器冷启；保留旧数据/包/证据，不误停其他项目。
5. 产品对照用户需求验收；开发交确定候选SHA、测试证据、资产复用结论、变化/风险给镜像线。缺陷交开发修复，不用放宽断言或改文字代替。
6. 打包/现场部署在对应用户授权后进行。华为验收也先停旧服务，但文档和只读取证不停止现有V3演示服务。旧state保留；V4默认不重新执行V3全量监控，新模型/新数据所需计算另列范围，不沿用V3全量许可作为永久许可。
7. 现场单Markdown核对后更新版本记忆；只有用户明确接受后记用户验收通过。模型业务安全/线上收益和离线计量证据分别记录。
