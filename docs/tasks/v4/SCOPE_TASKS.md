# V4范围、任务及完成标准

## 用户决定

V3已验收通过；V4核心是1汇报、2模型演进。希望小版本之间尽量复用Tokenizer和Chat Template。这是优化目标，不是未经核对就复用的授权，也不要求用改名掩盖实际编码差异。模型目标沿此前用户指定：Qwen3.6→3.8、GLM5.2→5.3、DeepSeekV4→V4.1；确切仓库/服务规格仍待证据。

## R：汇报（第一优先）

| 任务 | 首轮产出 | 完成标准 |
| --- | --- | --- |
| R0 产品定位与叙事 | 一页汇报主线、演示路线、事实与待证判断对照 | 围绕“看清业务请求/缓存→解释原因→给业务可执行建议→验证样本效果”，不一味扩张功能 |
| R1 已有成果可解释性 | 卡片文案/方案命名/状态与收益口径的最小改进建议 | 同类问题和不同模板方案分层；父集/样本/修改数清楚；独立收益不求和；原因覆盖受限与评估完成分开 |
| R2 汇报材料与DEMO | 汇报稿/讲解提纲；若涉及产品页面，先提供保留原布局的差异DEMO | 用户确认汇报表达；页面须明确“前端展示审批通过”后开发，不以本文件代替审批 |
| R3 需求验收 | 按获批稿与DEMO逐项核对，保留反例/限制 | 既有四入口/L4L5不偏移；真实、合成、样本、线上效果不混淆 |

可引用的已核数据：BUS01父1047/样本73，原样本31.93%，最高单方案43.27%（+11.34pp）；六clock分别+0.7132/+1.1355/+11.3415/+10.3231/+4.9395/+5.0853pp，不相加。ICSL合成102条35.95%→90.16%（+54.21pp），不是生产客户效果。BUS02某path方案P减414而C增34，说明不是所有改法都有收益。L4原因组128上限不代表丢失“810−128=682个问题”。引用时链接补证核对，不能用报告中的旧错误解释。

原产品线补充的已有基调为华为风、简约直观、四页、20分钟以内，优先复用现有宣传/四象限材料，详[产品上下文](../product-v4/ENTRY.md)。只有载体或范围变化时再与用户确认；不因要汇报就默认建设新的导出/幻灯片生成产品模块。领导材料优先业务模板/匿名编号，避免无必要地展示个人姓名工号或真实请求敏感内容。

## M：模型演进（第二核心，可先做只读核查）

| 任务 | 首轮产出 | 完成标准 |
| --- | --- | --- |
| M0 身份盘点 | 新旧模型规格/制品/别名及资产来源清单 | 确切ID/revision/模式有依据，未知不补猜 |
| M1 复用评估 | [逐模型核查矩阵](MODEL_REUSE_MATRIX.md)及最小差异方案 | Tokenizer和Template分别下结论；资产复用、编码等价、结果复用分开 |
| M2 实现方案 | 最小注册/锁文件/计量身份/API/UI影响清单和测试计划 | 用户认可实施范围；公共模型身份/后端契约先定，之后前端消费 |
| M3 获准实施与测试 | 固定候选与源/资产摘要、回归/旧结果兼容/内存证据 | 旧结果不重标新模型；新模型功能/模式可用，资源边界实测；不修改获批UI |
| M4 交付 | 审查交接、获授权构建、镜像/代码/现场prompt | 本机通过不冒称现场通过，包体仅本地backup管理 |

不预设新旧一定相同，不要求本机下载模型权重；TokenScope主要核验实际计量所需资产。新模型TTFT耗时需用户参数或现场标定，旧1/2.7/2.6秒不是新模型默认事实。

## 不在本期核心内

Token工具重复/巨大返回新开发保留为后续候选，当前不派单、不恢复Token私有规则；可引用已有研究解释未来价值，不把未实现能力用于演示。组合收益须明确批准再做联合回放，不能把简单求和当汇报优化。没有自动full、没有新增硬时间截止或跨项目调度。
