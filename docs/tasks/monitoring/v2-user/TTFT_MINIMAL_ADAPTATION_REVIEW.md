## 2. 接口及历史兼容建议

建议在情景中增加系统管理的计时模型标识（候选字段timing_model），区分旧W+O模型与新total_noncompute模型，估算结果随情景快照携带该身份。该标识不是现场采集参数。接口修订候选版本2.0.0，审批后冻结确切枚举、Schema与错误码；本轮不发布版本。

- 新情景保留model_id/common_name、简短deployment、chunk_tokens、chunk_seconds及来源说明。waiting_seconds沿用字段名，但在新计时模型下明确为全部非计算耗时；target_seconds/comparator及运行/appid引用不变。
- 新情景不接受overhead_seconds，避免出现“填0兼容”或重复扣减。无模型标识且符合完整旧Schema的请求只能解释为旧模型；不能凭O缺失自动判新模型或默认为0。
- user_assumption下的workload_description、thinking_mode、min/max_prompt_tokens、evidence_sha256、sample_count、calibration_notes不作为参考计算的必填采集项；有则保存。min/max成对提供且有序；缺失标未验证，不填假范围。measurement_boundary可采用固定GF口径说明，不要求现场日志作为必填证明。
- 仅batch时间有实测来源、其余仍是假设时，整套情景仍归user_assumption，并在source_description说明τ来源；不因有摘要/样本就自动晋级真实性能验证。已有verified_measurement历史标签保留其原语义，不追认新模型已验证。
- 推荐保留旧客户端按旧模型读写的兼容路径，严格按旧公式处理；新前端只创建新模型。旧历史页面可展示旧O且明确“历史W+O口径”。这不是在新方案继续要求O。
- 不重写已有scenario_id×revision或Evaluation快照；新口径另建revision。不得自动把旧W搬到新情景；如人工转换，须明确确认总W，不能假设旧W已覆盖全部耗时。
- 旧幂等提交返回原结果；输入冲突仍拒绝。未知模型版本明确拒绝，不回退默认公式。GET历史结果不触发计算。
- 保留现有端点和Evaluation主体结果字段；新模型无预算原因文字移除O。具体DTO/错误码及契约版本在获批实施批次统一冻结，旧冻结1.0.1材料保留。

## 3. 前端调整建议（交前端会话承接，尚未实施）

沿用UI-02布局。必填区域只含模型/配置、K/τ、T/比较符和W；L由所选CSV用户组提供。证据材料折叠为选填，不要求用占位值通过校验。

W标签为“首Token前非计算耗时预算（含等待等）”；5/10/20秒可作主动选择项，但不得自动选定。缺失不转0；明确输入0有效。K/τ不自动填合成示例；K显示确切整数Token。

新模型去掉O输入及缺O阻断；结果显示W/K/τ及假设说明，标题为“P90长度请求所需参考前缀命中率”。范围未验证、100%可行性未证实、无预算分别表达；不与聚合命中率作达标判断。实测τ也不能隐藏人工W与共享batch近似限制。

条件变化清除当前有效结果，迟到响应不得覆盖新条件；历史结果仅按原快照/版本展示。前端不自行重算公式。后端新契约可用前，不将简化表单接到旧接口；不以后台补O=0或伪造范围临时绕过。

## 4. 获批后验证与闭环门槛

后续在独立增量batch登记PLAN/ISSUES/TESTS/RESULT，不重开或改写U000–U005历史验收。建议顺序：契约及兼容冻结→后端实现与回归→前端接入与联合验收；每步通过再推进，前端工作由其负责会话承接。

必要验证：
- le/lt等号、T<W/T=W、尾chunk、n=0、nK≥L、无正P90、缺W与明确0、非法/非有限数和极端值。
- 新模型不扣O且拒绝O；可选材料缺失可运行但标未验证；提供范围时越界；模型身份不匹配拒绝。
- 历史W+O计算/快照/幂等重放一致，未知版本拒绝；revision冲突、重启读取、GET无写入。
- HTTP从最小情景创建→估算→读取→重启，核对精确结果和版本；相关契约/类型/静态检查及用户后端回归，确认V1/MA不受影响。
- 前端缺参保护、清除过期结果、人工来源标签、新旧历史展示与真实API联合；后端测试不能代签前端验收。

软件验收只证明实现符合本最小模型，不证明预测准确性。真实性能验证继续独立pending；不得因调整完成把三模型校准标完成。部署、打包不在审批范围。

审批要点：新模型去O、W改为总非计算耗时；证据字段选填；新旧计时模型显式区分并保留历史兼容；对应前端表单/展示及上述验证范围。
