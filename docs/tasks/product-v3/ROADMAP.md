## 3. 最小实验设计（仅方案，当前不执行）

| 实验 | 控制变量/基线 | 结果及失败条件 |
| --- | --- | --- |

| X2 高命中曲线 | 固定模型/精度/硬件/缓存层级，选代表性短/中/长输入及输出；h候选80/85/90/95/98%，预热与冷启动分开，保持可比到达/并发 | TTFT/TPOT/队列、KV搬运、GPU时间、goodput；能实现在块约束下的h才测；不支持拐点时输出连续曲线或不确定 |
| X3 网关重复分词 | 现有精确路径 vs 可信元数据复用/画像候选池；同输入与硬上限校验；时间留出 | 分词调用/CPU/端到端耗时、兜底和错分；任何越界放行失败，净收益无改善不推广 |
| X4 路由候选 | 固定到达序列、预热、节点和共享域；当前/均衡/亲和/受约束亲和；多seed仅用于随机策略 | 代理复用、偏斜、重映射/冷启动；有校准才报SLO；原策略不能解释观测时停止因果推荐 |
| X5 代表性与配比 | 原压测、真实联合配方、峰时/长尾压力配方；同服务配置，记录失败/超时 | 分布差异和性能曲线；需实例级曲线/共享干扰证据才能求配比，不能从请求长度比例直接推台数 |
| X6 场景改写质量 | 固定业务留出集，原请求与获准候选；任务指标和非劣界由业务方先定 | 同时报告质量、Token、命中、时延；质量不达标否决候选，即使Token更少 |

X2不要求一次全因子爆炸：先选最具业务量和可识别性的单模型/一套硬件，小批标定再缩小网格。无GPU预算先保留计划，不能用τ假设补造结果。运行重复次数和样本量以置信区间/功效需求决定，先定停止准则避免挑最好结果；长尾量不足报告不足。

## 4. 实施前必须明确的交接包

1. 用户已审阅的功能子集、优先级、非目标及成功标准；UIR-03是否纳入另有决定，不预设阻断。
2. 源数据授权范围、模型/模板/Tokenizer身份、字段可得性、共享域和业务质量责任人；缺字段对应降级行为。
3. 公共信息模型、任务状态、预算/覆盖计数、错误分类、版本兼容、旧运行读取和回退设计。由低命中后端作为公共层唯一维护方评审，不能研究会话冻结生产契约。
4. 统一编码/理想回放复用方案；新G/R能力如获准由监控维护方定义作用域，禁止原因分析另造一套Tokenizer或理想算法。
5. 各功能最小正例、合法负例、partial/unknown/不适用案例及验收口径；不只提供成功样例。
6. 真实预算试算与阶段上限、可恢复游标/产物身份；开发调试不构建镜像替代常规测试。
7. 前端接入说明和批准四入口/L4L5兼容清单。公共层先独立验收→依赖后端冻结→前端接入，六线不自动恢复。
8. 镜像打包与审查会话接手版本级bug协调、独立停旧冷启E2E、版本/Git与经授权打包交付。本研究会话交设计与研究证据，不自签版本验收。

## 5. 未来验收重点

- 可追溯：每个显示值能定位来源、窗口、有效分母和版本；混合来源不静默求差。
- 诚实状态：缺失/0/空样本、低潜力/未发现、不适用/预算截断有区分；partial不冒ready。
- 语义与质量：工具/消息变换未经业务验证不能标安全；重复字节不当节省Token。
- 计算边界：GET只读；预算/取消/恢复/结果缓存按身份；旧运行可读，禁全量二次编码。
- 决策价值：业务方能从每项结果选择“改提示词、补采集、测队列、评估路由、修正压测或暂不优化”之一，并理解依据。
- 性能声明：工作量代理、观测相关、对照因果分级；准入和台数必须有对应服务曲线及SLO验证。

## 6. 新报告到达后的增量流程

先核版本、数据量级/预算和V2用户监控/MA验收状态，研究不挤占既定两阶段验收；未指定appid不展开异常深挖。对每项观察建立证据记录：来源定位、范围/分母、支持/冲突、可靠性、影响功能和旧→新结论。新增r1或修订记录保留r0，不覆盖现场原文。若报告只给总体值而无可比性，保持不可判定。

当前最高优先级缺口：①cached语义与缺失/预热冲突；②实际长度/输出/到达联合分布和压测原件；③用户与MA关联/共享域；④指定appid结构正负例；⑤路由参数身份/分词耗时；⑥真实性能服务曲线。此排序服务证据依赖，不改变现场先监控后MA、指定后异常的授权顺序。

本轮未复现新的V2真实bug。如未来遇到，整理版本、最小复现、预期/实际、已有证据及影响供版本审查会话读取；不因研究推断重新开启旧修复任务。
