## 已有现场证据及初步文献核对

现场旧 [调查 §7原字节](../../../achieve/2026-11-05/hv2-acceptance-close/previous-evidence/docs/huawei/HUAWEI_V2_INVESTIGATION_REPORT_20261103.md) 只对指定的 10 个 appid 做研究，676 条结构样本；指定 DeepSeek 五个偏工具链、Qwen 有纯对话与混合。它与用户新增短请求观察可同时成立，不能将选定样本推广至全模型。旧报告发现 DS MA cached 全空、部分 GLM warmup_order_conflict、L1/L2 预算截断。HV2 已修复预算/可读性等，源数据问题和新版效果仍待现场。

2026-11-04 根会话初读以下一手来源，作为研究起点，不作为本项目真实性能证明：

1. [vLLM Automatic Prefix Caching，Limits](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)：复用主要减少 prefill，不直接减少 decode；缺少可共享前缀或 decode 主导时收益受限。因此应把命中收益与整链路成本分开。
2. [SGLang 论文，2024 修订版](https://arxiv.org/abs/2312.07104v2)：RadixAttention 在多种任务下复用 KV，支持研究前缀局部性；该论文不是我们的硬件/模型/数据性能标定。
3. [NanoFlow，OSDI 2025](https://www.usenix.org/conference/osdi25/presentation/zhu-kan)：其分析指出许多常见端到端负载仍算力受限，提示不能由某个 attention 阶段或一个命中率阈值直接推断全链路瓶颈。
4. [SGLang Model Gateway 官方文档](https://docs.sglang.io/docs/advanced_features/sgl_model_gateway)：cache-aware 路由结合局部性与负载；文档版本需记录，不能把默认参数迁移到未知的现场 MaaS 实现。

初步推导（本项目待验证）：若只看未缓存输入 Token，工作量比例为 `1-h`。80→85% 时剩余从20%降到15%，相对少25%；90→95%时从10%降到5%，相对少50%；85→95%时相对少约66.7%。这解释高命中区间相同百分点的潜在差异，**不是吞吐倍数、线性 GPU 成本模型或普适95%拐点的证明**。未缓存 token 数与固定开销、attention、decode、通信/内存、并发排队共同影响性能。

建议在本线目录形成 `RESEARCH.md`、`PRODUCT_DESIGN.md`、`EVIDENCE_MATRIX.md`、`ROADMAP.md`，按必要性合并，避免模板堆叠。

- 以一手论文、官方实现/文档为主，标注日期/版本、适用模型硬件与负载、局限；跟进用户提出的95%说法，查不到可信原始来源就保留假设，不能编出处。2026下半年趋势同样需证据。

- 每个候选功能列输入可得性、计算/存储预算、输出与用户决策、误报/不可判定、可复现实验和验收指标、依赖/兼容/回退。现有数据不足时仍能完成信息模型和可验证方案，不能等待报告后才开始。
- detector 候选先定义适用分母、正例/合法负例、标注和留出集、保留上限/扫描覆盖、质量约束和预期成本；不能用重复字节量当可节省 Token，不能默认删消息/重排工具语义不变。
- 离线路由比较要记录原时间顺序、预热、节点集合、负载约束及反事实限制。无生产队列/性能实测时只给缓存代理指标，不声称 SLO/吞吐实际提升。
