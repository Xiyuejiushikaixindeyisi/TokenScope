## 2. 为什么认同这个方向

现有监控与四象限已经能帮助挑选排查对象，但从“发现低命中”到“解释原因、给出修改、验证参考收益”仍有缺口。把 V3 聚焦在这条业务闭环，比同时扩展两类异常模块更容易检验产品是否真的帮助业务排障。

依据分开记录：

- **用户观察**：大文件任务可能卡住；本次所查 appid 只有 L4 有反馈，缺有效提升方案。这是需要解释的现场体验，不直接定性所有其他分析器失效。
- **已有现场证据**：[11-05 核对](../delivery/HV2_ACCEPTANCE_CLOSE_20261105.md)记录容器上限 32GiB、峰值 30.19GiB，以及超时/任务 Not Found；已列出的四个 partial 任务差异组均为 L4。没有足够 OOM-kill 和阶段证据，尚不能确认唯一内存根因。
- **已有负载证据**：[11-09 只读报告](../../huawei/TOKENSCOPE_PROMOTION_READONLY_20261109.md)中的六组指定对象均在当前长低象限。它支持优先排查，但不证明每组都存在可修复前缀问题，更不证明是 CCH。
- **判断**：用小样本先找可解释机制和可执行改法，符合“业务排障参考工具”的目标。全量收益估计可后置，不必作为每次排障给建议的前提。

Token 异常分析冷却合理：目前建议效果不足，先保留待解问题，待 V3.5 用长尾请求结构和业务必要性证据明确问题，再决定应开发哪些能力。不能由“建议少”推导“长内容都没有异常”或“长内容都应删除”。

## 3. 小样本方式：接受，但保留必要的可比性

“按时间戳取前 300 条”可作为第一轮排障窗口的候选，而不是已经确定的产品默认值。若不足 300 条就用已有有效请求；请求排序要有稳定的同时间戳次序，并记录源行/请求身份、起止时间、时区、截断与排除原因。

建议区分三种数据用途：

| 用途 | 范围与做法 | 可以说明什么 |
| --- | --- | --- |
| 当前总体画像 | 继续读取已完成的监控结果和直方图 | 观测窗口内原始命中率、长度、流量规模；不为本轮重新全量分析 |
| 原因探索 | 指定 appid×模型的小范围；检查 system/tools/messages、前缀分叉位置和相似请求对，必要时按模板/会话观察 | 该样本出现什么机制、现有规则在哪一环没形成可执行建议 |
| 修改对照 | 固定同一请求集合与先后顺序、同一编码/仿真参数和同样缓存初态，比较改前改后 | 样本上的命中变化、未命中 Token 变化、适用条件；不直接代替全量收益或线上 TTFT/吞吐 |

只取最早一段可能遗漏后续模板与场景。若首窗不能解释，下一轮 prompt 可在同一已授权对象、明确总预算内安排少量后续连续窗口或对照样本；不无条件扩大到全部时间、其他 appid。用于结构探索的分层样本不要任意拼接成“真实到达顺序”的缓存重放；各窗口的初态单列。最好另留少量不参与改法选择的样本复核，防止仅对发现问题的几条过拟合。

样本冷启动的基线可能与已有全量命中率不同，因此必须重新计算该样本的 before/after，不能拿全量 34.81% 和样本修改后的数值直接组成收益对照。若修改改变输入长度，同时记录 P/H/C 和分母，不能只看百分比。

资源限制不能只有“300 条”：还需限制单请求字节/Token、累计输入字节/Token、候选比较次数、编码次数、耗时和保留证据体积。限额应在加载/解析/计划扩张等昂贵阶段前生效；优先使用已有索引选取范围，不把完整大文件加载后再截取 300 条。仍需记录阶段内存和停止原因，不承诺小样本天然不会超限。

## 6. 下轮华为探索需要留下的可开发证据

这是下一轮 prompt 的输入要求，本轮不生成或发送执行文本。

单一 Markdown 必须让外网机不依赖华为本地路径也能理解关键结论。每个对象至少包含：源/版本/样本选择与预算；请求结构和可能业务用途；前缀首次分叉及最小 before/reference 片段；假设、反证和适用分母；候选修改及业务语义风险；同样本对照或无法评估的原因；现有分析器漏在何处；可复用的旧规则改进或新规则候选。

“关键证据嵌入正文”包括字段路径、请求定位、必要脱敏片段、计数表和对照数据，不能只给本地文件链接。脱敏需保留差异位置/结构关系；正文片段不替代原始字节重放，报告中的数值应在现场原始授权样本上计算。无须外传整份敏感原始请求。

每项候选规则至少给一个支持例、一个合法差异或反例，以及适用/不适用条件。结论允许是“可优化”“业务必要差异”“证据不足”或混合，不能为了增加分析器强行产出修复。L4 差异是线索，需继续判断差异发生在哪里、为何阻断复用、哪些部分可调整。

未来实施建议按以下顺序收敛：有限范围任务和稳定性 → 六组真实原因与既有链路缺口 → 可执行改法与样本验证 → 复用性明确的新探测器。验收关注证据可定位、改法有约束、收益范围清楚、无发现有解释、资源停止可理解；不以六组全部达到高命中或新增探测器数量作为成功标准。公共层/后端/前端/独立验收仍按原职责推进，保留四入口与 L4/L5，旧成果可读。
