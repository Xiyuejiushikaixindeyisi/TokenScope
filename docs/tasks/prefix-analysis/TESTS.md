## prefix-design-0.2新增必测项（实现依据）

- 手动原因/开关矩阵：low_hit为true/true且低命中评估结束后Token；长度/QPS为false/true；冲突拒绝；无阈值自动启动，无发现仍执行Token，共享源失败及中断不继续。
- L1/L3动态业务路径/时间可生成删除假设，无业务无损审批也能离线实验；准确范围、原值guard及合法结构保护；不擅自上线修改。此项覆盖旧表“业务时间不直接删”的离线限制。
- 小范围连续序列包括未修改请求；前后同空账本，不挪用原全范围H、不反复挑优样本；范围不足显式记录。变换版本一致才从pilot晋级full。
- 未舍入ΔR为0.99/1.00/1.01pp分别不通过/不通过/通过；0及负收益保存但不展示优化卡片；P=0不可判定。小范围通过而全范围不通过不得展示；小范围失败不发布after。
- 单项互相遮挡、组合独立通过：不把组合收益记给单项；全范围包含未改后继请求，P/H/C/R与修改子集分别保存。
- L4/L5两条完整JSON可读取，真实原文摘要可核对，不以block/preview替代；未知关联不判同session。无收益证据及Token报告不套用低命中门槛。
- 公共draft-2：raw_body_complete与capture_truncation独立、三态参与及nullable spans、TA-C0.2三层身份/纯handler/内嵌JSON原子应用、跨方向冲突、预算停止协议。

以上是设计检查项；具体已执行覆盖与结果须对照各批 RESULT 及本次自审记录，不能由清单本身推导通过。

性能测试记录appid请求数、正文/IDs体量、候选数、编码次数、峰值内存、耗时与预算覆盖；本地实测见 RESOURCE_PROFILE，现场吞吐/时延尚无承诺。已有业务判据不因预算耗尽被改为更宽松门槛。
