## N1 完成及终态通知

需求：报告封存并可读后，通知前端拉取；无报告的failed/interrupted/empty等终态也应让用户知道任务结束，单项评估/授权评估同样适用。推荐SSE，具体路由和事件结构由公共维护方设计；本文件不预定可调用的URL。

最少语义：服务实例/协议版本、可恢复事件标识或游标、task_id、任务种类（诊断或评估）、终态、报告是否已发布、可关联的报告身份/目录版本；评估需要父任务/原scope关联。事件不承载完整原文，不直接作为业务指标来源。报告发布通知必须发生在持久化提交且GET可读之后，封存/事件之间崩溃不得造成永久漏发现。

重复通知须可去重，乱序不得使当前报告倒退。打开时取得目录并衔接订阅须消除两者之间的丢事件窗口，可采用同一快照游标+可回放日志或等效机制。断线恢复补发/目录对齐；游标过期或实例变化有明确reset/重新同步语义。心跳不查询结果、不执行分析。没有通知能力时前端不静默回退轮询。

必须明确实例隔离和订阅方式：现有诊断头为x-tokenscope-service-instance，原生EventSource不能自定义该头，需后端与前端选择fetch流式SSE或明确且安全的替代实例校验方案；不得偷偷去掉实例保护。沿用部署已有访问控制，不新引入未讨论凭证协议。

## N2 持久化报告目录

需求：打开/重连能发现离线期间成果，列出有历史分析的appid，以及该appid对应模型服务、类别的已发布报告。浏览器本地任务列表不足以承担这个职责。目录为只读，不触发诊断或更新计算。

目录至少表达：实例、稳定报告身份/task_id、appid、源绑定模型服务身份、诊断类别/方向、scope及数据窗口、报告完整性/发布状态、可信完成时间、读取成果引用、用于一致性判断的目录版本。字段命名/类型/分页协议由后端提出；整数/时间仍遵循无损wire约定。不得将report_ref当任意文件URL。

默认报告选择必须由后端给出确定语义或明确权威引用：建议按明确发布顺序选择可替换的完整诊断报告，不由前端用读取时间/本地到达顺序选latest。请明确旧窗口晚完成、重试、多模型同appid、多方向及显式历史查看的处理。数据窗口时间与完成时间分开，不隐含按数据新旧或完成先后选择。首次partial/empty选择规则见N4待确认。

必须支持稳定分页/目录变化检测，避免跨页混合两个目录版本；明确重复、删除/保留、未知实例和空目录语义。只含真实历史报告的范围；有历史但没有建议的报告仍是报告，不能以卡片数为0删除该appid。单项评估成果与主诊断目录分开关联，不能作为应用最新诊断覆盖原报告。

历史保留不随监控新批次清空；若服务有清理机制，应显式说明保留策略，不能承诺已删除报告可读。打开/重连对齐目录后，可按已知task进行一次性恢复查询以补齐无报告终态/评估任务；不是定时轮询。也可提供等效终态恢复机制，由维护方选择。

## N3 完成时间

需求：后端持久化提供可信分析完成时间，便于持续展示一个月前的报告；结果和时间绑定同一报告身份。请区分任务终态时间、报告发布时刻、分析数据窗口，如二者时间不同不能混称。前端推荐业务标签为“分析完成时间”，北京时区展示并保留UTC原值。

建议以报告封存完成时刻作为业务报告时间；字段名、精度、来源由后端冻结。不得用服务重启、文件mtime、浏览器首次读取时间回填旧报告。历史缺失时间返回明确null/未知，页面显示未提供；无需为填时间重算历史分析。重试与评估子任务有各自时间，不改写原报告时间。

## N4 发布资格、partial与评估边界

新诊断尚未完成：旧报告和旧完成时间保持。新完整报告已发布：前端读取/校验成功后整体切换结果和时间，拉取失败保留旧成果。partial：不自动覆盖旧默认报告，可提示并显式查看已完成证据；规则限制不能解释为全量正常。failed/interrupted同样不替换。

请明确并反馈以下情况，不由前端猜：首次只有partial是否进入历史目录但无默认完整报告；empty是否作为历史报告、是否替换旧报告；TaskReceipt ready与方向完整性的关系；一次low_hit包含两个方向时，一个方向不完整是否允许另一方向独立成为默认报告。用户尚未确认这些扩展规则，默认不得以它们覆盖已有完整报告。

单项评估：新task结束通知驱动evaluation/plan读取，父任务及证据可回溯；blocked或准备阶段受阻可能只有reason_codes、stages=[]且无evaluation，通知不能承诺一定有结果对象。Token/combined零负收益保留，不套低命中>1pp门槛；无after不补零。组合暂不放主流程，不要求本次扩展组合UI。

## 最低验收场景（未来实施后执行）

1. 新分析运行数小时不发生周期receipt/report GET；历史报告及时间稳定，无历史appid不出现空报告卡。
2. 报告提交后发通知，GET立即可读，结果和时间整体更新；读失败可显式恢复且不清空旧报告。
3. 用户离线期间完成，打开目录即可发现；目录读取与订阅之间完成也不漏；无报告的失败终态可恢复。
4. 重复/乱序事件、断线重连、游标过期/reset、实例更换，不倒退或串实例；分页期间新发布不混快照。
5. partial不替换旧默认报告；失败/中断不替换；首次partial、empty及方向局部完整按最终确定规则验证。
6. 跨模型同appid与Token-only报告正确归属；有报告但无建议仍在目录；评估子任务不覆盖诊断报告。
7. 旧报告时间null诚实显示，数据窗口/完成时间分开；新监控批次不清空历史。
8. Token显式评估/授权及低命中direct_full的完成/阻断/失败可通知恢复；保留父任务、零负收益和原文，GET无计算副作用。
