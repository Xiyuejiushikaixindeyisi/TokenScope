## 卡片和详情

两类均保留UI-01侧栏、顶栏、应用/模型范围栏、两类导航、双列卡片及窄屏单列断点。移除卡片置信度、覆盖率与对应排序，不补造影响请求数。能力说明分别为低命中5类/Token4类，默认折叠；能力数量不等于每次执行完整数量。

低命中优化卡片：业务标题、一句话问题、建议、全范围命中率及计算Token变化、详情入口。只有完整full/direct_full且服务判定严格>1pp才属于优化建议。差异卡片展示事实及查看对比，不留虚假收益指标。

低命中详情：发现了什么（两条完整请求及各自路径）→建议怎么改（建议/业务注意事项，没有可评估方案时说明）→修改后效果（全范围优先，小范围和实验说明折叠）。L4无会话关联就地提示，LCP不等于实际缓存边界，direct_full应说明直接评估。

Token卡片：内容事实/策略不符合/重复内容/保留规则标签，标题、事实、建议及详情；度量注明单位，参与未知不折算Token，无业务policy不判超限。尚无评估不写预计节省；已有评估同时展示P/C变化，零负值保留。

Token详情：内容在哪里（同请求多位置、全文按需展开）→可以怎样调整（单项参数/业务依据按需展开）→本次修改的效果（P/C为主，命中率辅助，受阻无after）。T3不预选删除授权，不编造业务依据；T4未填与0区分；单项收益不相加。

必要未检查提示仅在实际存在限制时出现；任务反馈不混进建议排序，新任务失败/等待不能清空旧报告。无分析时间显示未提供。更完整的任务管理、参数表单、缓存及错误恢复待HTML审批后的正式交互阶段确定。
