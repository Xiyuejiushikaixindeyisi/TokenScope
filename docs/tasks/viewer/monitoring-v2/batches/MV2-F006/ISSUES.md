# 实际发现与修复

1. 刷新浏览器后原先只能恢复跟踪任务，不能恢复失败任务下的历史展示。增加按服务隔离的最后展示run/APPID元数据，先只读恢复历史，再跟踪当前任务；用户和MA均有浏览器验证。
2. 提交响应丢失后再次点确认原先会新建key。现在相同未确认输入沿用原key；真实HTTP已受理但模拟丢响应后验证同key恢复。明确4xx拒绝与网络结果待确认分别提示。
3. 人工对照UI-02修正TTFT中/右列顺序，MA摘要三个位置和表列顺序、详情趋势/分布页签、窄屏重复导航；保留主配色和六卡三图。MA小速率改有效数字格式，避免非零每秒速率显示成0。
4. MA压力说明按实际源码明确为request_time分桶；model_handle_start_time只作处理范围补充，不误称到达QPS/GPU吞吐。未修改统计或后端契约。
5. 启动核对用户操作2.0.0，服务身份变化停止旧视图与任务；不会把旧服务提交转发到新服务。排行revision持续冲突最多自动重读一次；众数验证run/APPID/revision。
6. 验证脚本初次用户状态探针未带身份header；一次定位器命中隐藏排行中的同名文字；Node JSON导入缺少属性；绑定测试误用被用户提交预留的base。均修正测试前提/定位，不放宽契约。完整首轮24通过/1定位器失败日志保留browser-first.log；最终结果见TESTS。

## 保留限制

- 合成CSV和模拟故障验证前端接入，不是生产性能或华为现场验收；真实TTFT性能校准仍待完成。
- 每60秒是活跃页面调度周期；浏览器后台节流不保证墙钟时限。关闭浏览器后不继续监视。
- 初次APPID下拉最多1000项；后端排行可访问其余候选，不在前端截断全局排行。历史用户运行/情景无列表API，采用已知ID与本机最近。
- Vite主包大于500kB有体积提示；本地构建成功，gzip约166kB。未为消除提示引入新依赖或更改门槛。
- 未部署、打包、改变服务资产、后端算法/契约或异常分析模块。
