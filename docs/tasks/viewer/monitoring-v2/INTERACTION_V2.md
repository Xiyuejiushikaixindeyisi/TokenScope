2026-10-31 · v0.2。①已按最新决定更新，②–⑤已认可；分批开发计划待评审。维护：01a18c49-d9b4-7a33-8c04-e5a72adfcc24。本文第10节为最新任务刷新规则，第11节替代旧第6节TTFT字段要求。

用户已认可UI-02，并明确用户监控及MA后端均完成开发、评审通过。本稿以此为前提设计正式交互，不重复审批后端。本稿尚待用户认可；未修改HTML、正式源码或契约。

## 1. 基线与页面结构

视觉采用[UI-02](prototypes/tokenscope-v2-demo-ui02.html)，保持侧栏、配色、布局与信息密度。用户页六卡三图、TTFT三栏、排行筛选表格、MA全UUID表及下方双页签保持。移除合成数据条、结果样例选择器和演示状态；以真实回执和数据替代。新建/打开运行及情景管理放现有范围栏按钮和弹窗，不增加常驻大面板。

依据：[用户交接](../../monitoring/v2-user/FRONTEND_HANDOFF.md)、[用户实际API](../../monitoring/v2-user/IMPLEMENTED_API.md)、[用户契约1.0.1](../../../contracts/user-monitoring-v2/README.md)、[MA交接](../../monitoring/v2-ma/FRONTEND_HANDOFF.md)、[MA实际API](../../monitoring/v2-ma/IMPLEMENTED_API.md)、[MA契约1.0.0](../../../contracts/ma-monitoring-v2/CONTRACT.md)、[S0实际API](../../../contracts/MONITORING_IMPLEMENTED_API.md)。字段约束以各Schema为准；UI-02合成投影不是接口DTO。

## 2. 共同操作与状态规则

| 操作/状态 | 正式行为 |
| --- | --- |
| 首次进入 | 读取GET /monitoring/catalog取得service_instance_id；恢复当前服务下的导航记录并重新读取回执。没有记录时显示“打开运行 / 新建分析”，不自动创建任务 |
| 服务身份 | user-v2和MA请求携带X-TokenScope-Instance-Id。服务身份、业务run、MA UUID分别保存；身份变化清除旧选择和结果缓存，提示重新选择，不自动重发写请求 |
| 切范围 | 立即显示目标范围的加载态；旧数字不留在新标题下。取消旧请求或忽略过期响应，只有身份、run、分组均匹配才接收 |
| 页面加载失败 | 在对应卡片/表格显示失败原因和“重试读取”；不将失败显示成空数据或0。刷新同一已加载范围失败可保留旧快照并明确标“上次成功结果，刷新失败” |
| 已提交任务 | 显示独立任务条；非终态每60秒GET状态，完成/失败/中断停止。失败保留历史，完成加载新结果；历史列表手动刷新。详见第10节 |
| 写操作 | 点击提交前固定请求内容和幂等键；请求中禁用重复提交。超时显示“提交结果待确认”，保留原键及原内容，禁止直接换键重做 |
| 返回/刷新浏览器 | URL保留类型、run、APPID或UUID等可定位身份；筛选/页签恢复后重读。文件引用、正文和情景说明不进URL。本机记录仅存必要ID、提交恢复信息和界面偏好，不存请求正文 |
| 数值/时间 | Token、计数、revision保留十进制字符串，不经Number损失精度；排序与统计由后端完成。百分比仅作精确单位换算。UTC保留原值、展示北京时间，输入明确时区 |

所有读取仅访问既有结果。查询、切页、切图和展开详情都不触发编码、回放或索引重建。旧S0的ETag/304继续按原协议使用；user-v2遵循no-store，不套用S0的HTTP缓存规则。页面内结果缓存须按服务身份、业务类型、run及分组隔离。

## 3. 用户监控：运行选择与生命周期

范围固定为一个user_run对应的common_name及一个APPID。显示服务名和模型身份，不用UI-02内部模型缩写当接口model_id。模型使用Schema枚举，服务名独立绑定。

范围栏“分析结果”打开弹窗，提供三条路径：

1. **新建用户分析**：填写受控输入目录内的file_ref、common_name、model_id，确认后POST /monitoring/user-v2/runs。没有HTTP文件上传或自动目录扫描，页面不接受本机任意文件作为已上传文件。
2. **打开用户运行**：输入已知user_run_id，GET回执校验后加入“本机最近打开”。通过分享运行链接也走同一校验。列表明确仅代表当前浏览器记录，不声称服务端全量历史。
3. **接入已有基础结果**：从旧S0历史运行选择base_run_id，核实模型和来源后显式填写common_name，POST /monitoring/user-v2/bindings。绑定用于创建用户扩展索引，不重新编码；不能把base_run_id直接用于排行/估算。预留或绑定冲突按错误提示处理，不自动改服务名绕过。

| 回执状态 | 页面与允许操作 |
| --- | --- |
| accepted / base_pending | 显示“已受理 / 基础分析处理中”；可刷新、离开页面，不显示虚构指标 |
| indexing | 显示“排行索引准备中”；基础run已完成且S0读取成功时可查看六卡三图/明细；排行与新评估等待ready |
| ready | 保留user_run_id、base_run_id、common_name、index_revision；开启排行、众数与评估 |
| empty | 无有效用户组，显示文件质量与有效子集说明；不虚构APPID、0%命中或P90 |
| failed / interrupted | 显示安全原因及“刷新状态 / 新建分析”；新建是明确的新任务。临时存储错误优先重读，REANALYSIS_REQUIRED需重新分析，不在页面偷偷重建索引 |

用户接口没有按submission_key查回的GET。若POST响应丢失且尚无user_run_id，使用原键、原内容重发对应POST来恢复幂等回执；已拿到ID则GET回执。确认修改输入或另起任务才生成新键。

切服务时只展示该服务对应的已知运行；没有可用运行就进入选择态，不沿用其他服务数据。旧S0目录不能自动推导user_run绑定。

## 5. 搜索与排行

GET /monitoring/user-v2/runs/{user_run_id}/rankings。默认request_count降序、5K箱；四指标严格为request_count、ideal_hit_rate、total_ideal_compute_tokens、typical_ideal_compute_tokens。

搜索输入停顿300ms或按Enter执行查询；APPID大小写敏感，%/_为字面字符。排序、方向、箱宽改变立即查询并回第一页。数值条件先编辑草稿，点击“应用条件”才提交；收起时显示生效条件数，清空后重新查询。上下界包含端点并AND组合；请求数/总Token为整数，均值允许精确小数，命中率输入0–100%后转0–1。非法、倒置或超契约长度的输入就地提示，不发送请求。

正式建议每页20条，显示匹配total及当前区间；使用next_offset和固定index_revision。后续页带同一run、箱宽、筛选、排序及revision；返回上一页保存其offset。版本冲突丢弃旧分页链，保留筛选并重读首屏，提示“结果版本已更新”。不在浏览器排序当前页冒充全局榜单；缺值末尾，显示“—”及可用原因。

典型值显示后端均值、代表箱和tie_count；点击“查看众数区间”请求同run的/modes（appid必填），按同一箱宽及revision分页加载全部并列峰。超过200K仍是开放等宽箱。明细弹窗不把未加载峰称为全部。

点击“查看监控”携带user_run、base_run和APPID；返回排行恢复搜索、已应用条件、排序、箱宽、页码及滚动位置，重读时仍校验revision。无匹配、运行empty、索引未就绪和读取失败使用不同文案。

## 6. TTFT条件、情景与评估（1.0.1历史方案，已由第11节替代）

维持“条件 → 所需参考命中率 → 本组P90”的三栏。默认W为空、情景未选择；不得自动带入合成τ/K/O或历史W。缺任何必需参数时命中率为“—/参数未齐”，显示“代码完成，性能校准待完成”，不允许POST评估。先检查原始输入是否空白，再数值转换；禁止Number(空字符串)、||0或??0把缺失等待变成0。明确填写0允许作为有来源/假设的情景，不能因此称实测已校准。目标T>0，W≥0，允许契约支持的精确小数，不继承HTML的1–60/0–10整数范围限制；比较符映射le/lt。

“设置评估条件”弹窗内有“打开已知情景”和“登记新情景”。已知情景按scenario_id/revision GET读取；最近使用只记录本机ID，不假设存在情景目录API。读取后展示部署、模型/服务、思考模式、计时边界、负载描述、输入长度范围、K/τ/O、来源、样本数及校准说明。

登记情景填写Schema要求的上述字段以及ID/revision、source_description、evidence_sha256。人工假设明确标记；实测来源要求证据摘要与正样本数，不因source枚举叫verified_measurement就声称系统核验过证据。K/τ>0、O≥0、长度范围有效；保存调用POST /scenarios。同ID/revision不可覆盖，修改须新revision；冲突不自动覆盖或自动递增。缺τ不能注册有效情景，不在前端补默认性能参数。

应用条件仅保存当前选择并置“待重新评估”。点击“评估”才POST /evaluations：submission_key、user_run_id、appid、scenario_id、scenario_revision、target_seconds、waiting_seconds、comparator。请求中显示评估中；成功使用返回的prompt_p90/request_count及参考结果，避免与另一个快照的P90拼接。保存evaluation_id，可GET /evaluations/{evaluation_id}查看历史固定快照。响应丢失时同键同内容重发POST恢复，不新建多份评估。

| 变化/结果 | 展示 |
| --- | --- |
| 缺K/τ/O/W，或等待空白/null | 参数未齐，清除当前旧比例，禁止发送不完整请求；后端422不携带命中率，不补0 |
| run、APPID、目标、W、比较符、情景revision变化 | 当前结果失效为待重评；若旧请求随后返回，只保存到对应历史，不覆盖新条件 |
| reference | 显示参考比例与情景限制；0%说明本情景预算不需缓存，不代表生产达标 |
| reference_with_limit | 100%并提示理想化完全复用的实际可行性未证实 |
| no_budget | 显示无计算预算及原因，不填0% |
| out_of_scope | 显示超适用范围，允许更换合适情景 |
| unavailable | 展示后端reason/limitations；缺有效正P90等不补值 |
| 请求失败/参数错误 | 保留输入，显示错误与重试；不同于业务不可用状态 |

不把总体ΣH/ΣP与参考比例比较后宣布SLO达标，不在浏览器实现TTFT公式。

## 7. MA运行、全UUID与实例画像

范围栏选择规格后，GET /monitoring/ma/catalog?model_standard_name=...读取完成运行；默认选该规格最新完成项，显式历史链接则固定指定run。目录分页固定catalog_revision，冲突重新从首屏读取；不把未加载目录页称为全部历史。目录刷新保留已选运行，不静默跳到新结果，另提示可选新运行。

“新建MA分析”弹窗显式填写pre/now两份受控文件引用、规格、编码模型及连续窗口；均1小时，source_timezone固定UTC。界面显示北京时间及对应UTC，提交前确认pre/now角色，不能仅按文件名推断。POST /monitoring/ma/runs，保存ma_run_id/submission_key。响应丢失先GET /submissions/{submission_key}查回；404且仍待确认时允许原键原内容重发，不换键重复计算。

| 回执状态 | 页面行为 |
| --- | --- |
| queued / running | 显示排队/处理中，可手动刷新；目录仅含完成运行，不能用目录缺项判断提交失败 |
| completed | 刷新目录或按已知run读取成果；empty_scope_reason区分空文件与全部不可归属，仍保留目录给出的仅pre UUID |
| failed / interrupted | 显示error_code及安全定位；无完整结果不显示零曲线；重新运行需明确新提交，不续接旧缓存 |

选择完成运行即按目录instance_uuids列出全部行，UUID稳定排序。每行GET /runs/{ma_run_id}/instances/{instance_uuid}取得概览与详情共用快照。建议最多4个并发读取；所有行立即出现占位，逐行填数，单行失败保留位置并可独立重试。不得仅加载一个选中UUID，也不把“全部实例”误写为都已成功加载。

表格消费paired_ideal/paired_real、两项coverage、hour请求速率/uncached速率/总量；摘要仅显示UUID数和pre/now时长，不计算额外规格总量。配对两值不可用时均为“—”，独立可用指标仍在详情展示。

展开任一行复用其快照，原两列区切换“流量趋势／长度分布”；切页签、1K/2K/5K箱宽、计数/占比不再调用分析接口。趋势用12桶和hour均值；分布各用自己的sample_count/quantiles/modes，保留200K尾桶与zero_uncached_count。空桶为0、有请求但真实字段全无效为null并断开；部分有效显示覆盖，不插值补线。

独立指标折叠区展示real/ideal、配对分母、mismatched_input_count、pre有效数、ideal_status与runtime限制。无有效预热不等于线上冷缓存；预热冲突不抹除真实数据；仅pre行保留且now命中率为空。真实高于理想不自动标红或解释为路由损失。

“数据质量”GET /runs/{ma_run_id}/quality分页，按pre/now、记录位置、字段、原因展示；无UUID筛选能力，不把它标成当前UUID专属。失败/未完成任务只展示回执错误，不能冒充有完整质量报告。MA不提供原文导出、自动告警、SSE或路由切换操作。

## 8. 错误恢复与接口边界

| 错误 | 动作 |
| --- | --- |
| 服务身份409 | 停止旧请求，重新获取身份、清除旧范围，用户重新打开运行；不把旧POST转发到新服务 |
| RESULT_NOT_READY / INDEX_NOT_READY | 回到任务状态提示，可刷新；不触发重建 |
| INDEX_REVISION_CONFLICT / CATALOG_REVISION_CONFLICT | 保留条件，丢弃分页链，重读第一页；不得拼接新旧结果 |
| 404运行/UUID/情景 | 明确对象不存在或不属于当前服务，允许重新选择；不自动切最新结果掩盖错误 |
| 提交键/情景冲突409 | 保留输入、展示冲突；确认新任务或新revision后才换身份 |
| 422 | 字段旁提示并保留草稿；不输出原始请求正文或敏感路径 |
| 503/断网/超时 | 读请求可重试；写请求进入结果待确认并按各自幂等流程查回；保留当前任务身份 |
| 封存损坏/INPUT_CHANGED等 | 展示不可用原因，停止将该结果用于对照；由维护处理或用户显式新建，不自动修复 |

本方案不要求新增后端接口。用户运行与情景缺少列表的现状，通过“已知ID/显式提交或绑定/本机最近记录”完成首版路径；如果产品必须支持跨浏览器全量发现，再单独讨论目录能力，不能由本地记录冒充。

2. B成功后读取其发布结果，读取成功才整体切换标题、run和指标。“最近分析”指所跟踪任务在对应服务/规格的新完成结果，不自动跳到其他服务或无关运行。空结果展示B真实空态并提供返回历史入口，不把A冒充B。
3. B失败/中断时继续展示A，在独立任务条显示原因。B成功但结果读取失败也先保留A，提示“新分析已完成，结果加载失败”，重试只读结果，不重跑任务。
4. 完成后的定向加载不启动历史目录轮询；MA定位完成项确有需要时允许一次目录读取。历史列表整体仍由用户手动刷新。

6. 离开任务页面停止查询，重新进入立即读取，仍非终态才恢复60秒。浏览器后台节流可能延迟，恢复可见时核对一次，不承诺严格实时。晚到响应不得抢占已切换的服务/规格或不同导航代次。
