## 3. 关键验收场景

1. 展示历史A，提交任务B：处理中仍显示A，任务条显示B。在第60秒读取B；B失败/中断后停止定时读取，A的范围、数据和图表不变，错误条可见。
2. 同样起点，B完成：停止状态查询，读取B的发布结果；读取成功后标题、run、表格、图表一起切B。读取失败时保留A并明确“B已完成，结果加载失败”，只重试读取，不重跑B。
3. B完成但有效结果为空：显示B的真实空态并提供返回历史A入口；不能把A冒充B，也不能因空结果继续无限轮询。用户empty与MA completed/empty_scope均覆盖。
4. 查询B时用户切服务/规格或离开页面：旧响应不能抢占新范围；返回当前任务立即读状态，非终态才恢复60秒查询。服务身份变化后禁止旧提交自动转发。
5. 断网/503不算任务终态：提示状态暂不可确认，保留A与B身份；继续按60秒间隔尝试读取，用户可手动重试。不调用提交接口轮询。
6. 历史列表不定时刷新；跟踪B完成时按B的已知ID加载，仅在MA定位完成项确有需要时做一次目录读取，不启动历史目录轮询、不切换到无关规格或其他任务。

浏览器后台节流可能延迟定时器；不承诺后台页面严格60秒内通知。页面恢复可见时立即查一次，不补发错过的多个周期。单一服务/任务共用一个跟踪器，组件重挂载不产生多个定时器。

计划涉及app.tsx、styles/base.css、api与state/storage公共模块；实施前在SESSIONS按批次登记具体文件及唯一维护方。本计划不构成现在占用源码窗口，不自动唤醒或通知其他会话。

本机最近记录按服务身份隔离，区别回执恢复资料和不可变结果。改变storage版本时须测试旧浏览器数据迁移/异常恢复；不得通过清库消除失败。后端新情景兼容方向按2.0.0说明，不通过删除新历史回退旧后端。

每批保持可独立审查的源码差异和恢复点；只回退本批前端改动，不重置共享工作区或触碰其他会话文件。计划内Vite构建仅用于本地静态产物检查，不构建Docker或交付包。未来源码Git合并/push遵循项目规则，当前只交计划不提交他人修改。
