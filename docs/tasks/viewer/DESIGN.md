## 分析报告展示 v0.2：面向业务应用

2026-10-27 用户修订覆盖旧报告列表设计；[v0.1 历史稿](../../archive/viewer/DESIGN_report-v0.1.md)只用于追溯。当前交互 HTML 与监控原有界面保持相同的浅色、低饱和度风格。所有探测结果、置信度、覆盖率和收益均为明确标记的合成样例，真实内容由分析模块决定。

### 范围与导航

进入报告时继承监控中的 appid 和模型。先选业务应用，再选该应用的模型；该范围下分为“低命中率”“Token 异常”两类。模型是业务范围的一部分，不组织面向推理加速人员的模型研究报告。切换范围后只展示当前范围的建议；详情始终保留范围选择。返回监控同步范围。URL 保存范围、类别与建议，兼容旧原型的 prefix-glm/token-glm 链接。

### 卡片与详情

每张卡片对应一个小探测器输出的具体问题，采用业务能理解的标题与描述。卡片展示影响请求数、置信度、评估覆盖率、修改建议摘要与后端提供的收益。详情分三段：

1. 问题发生在哪里：业务位置、后端提供的断点或字段路径、请求对照/工具返回构成/调用记录等可用证据。
2. 怎样修改：建议、修改例子、业务语义注意事项；支持复制建议，不修改生产请求。
3. 修改收益：后端提供的前后命中率、百分点或 Token 减少量及其评估范围。没有量化收益时显示定性建议，不编造估计。

LCP 差异位置与实际可复用边界分开解释；只有业务位置时不虚构精确 Token 坐标。原请求与模板后片段切换依赖真实映射。调用片段不代表完整 session/turn。单项收益不可直接累加，只有后端提供组合评估时才能展示组合收益。

### 排序与完成率口径

默认影响请求数降序，同值按置信度、评估覆盖率依次降序；支持用户切换命中率提升、输入 Token 减少、置信度或评估覆盖率作为首要排序字段。缺失值排在已知值之后，不使用未经讨论的加权分数。

本版将“完成率”暂时表达为**评估覆盖率**：受影响请求中已有评估结果的比例，与任务运行进度、原因置信度不同。此定义须在前后端接口阶段共同确认；当前数值为后端样例字段，前端不计算分析覆盖情况。

收益排序只能比较相同单位、相同范围的值。命中率使用百分点；本原型 Token 卡片使用每条受影响请求的输入减少量。详情可展示有明确范围的调用序列收益。正式接口需提供比较口径，不能混排总量、均值、百分比或不同基线。

### 业务界面状态

业务报告不展示“未完成、处理中、部分结果、失败”等分析任务状态，不提供任务状态筛选。展示已发布建议；没有建议时使用“当前范围暂无已发布的优化建议”，不推断应用没有问题。缺少证据或量化评估仍诚实说明，不把数据缺失伪装为完整结论。

任务运行状态如何向管理者提供属于后续交互设计，不在本版业务卡片中展开。生产接口读取错误也不能伪装成空结果，其呈现方式后续协商。

### 组件及后端边界

前端组件：应用/模型范围选择、两类标签页、建议排序与卡片、问题位置与证据、修改建议与例子、收益对照。report-ui.js 管理范围、路由和排序；report-evidence.js 渲染可选证据。页面读取已有结果，不触发编码、缓存仿真、判因或探测器运行。

展示最小输入包括范围/窗口、建议与探测器标识、业务描述、影响量、置信度/覆盖率及定义、位置/证据/例子、建议、收益及单位/评估范围。这是交互需求，不是已冻结的后端 Schema；分析模块决定哪些内容能提供。当前各模型是否有实际建议不能从合成样例推断。

### 验证与下一步

桌面和 390px 窄屏检查范围隔离、排序、位置/建议/收益、深链接、返回监控及离线运行；原监控交互回归通过。入口、脚本、验证摘要和冻结版本见 [CODEMAP](CODEMAP.md)。下一步基于用户对新版界面的反馈共同设计监控前后端交互与流畅性，不提前实现分析算法或接口。

## 2026-10-27 更新：完整快照、缓存与当前范围

最新用户约束覆盖此前“首选轮询”的调研建议：

- 当前仅推进 Token 监控的前后端交互和展示。低命中率/Token 异常分析的正式交互与详细展示，等各自分析器完成设计后再继续；已有 HTML 是获批视觉参考，不等于分析接口冻结。
- 监控只展示完整计算结果，不随计算进度改变数值。现有监控 DESIGN 第 10 节按整个 run 封存发布；沿用此边界，不擅自改为每 appid 提前发布，后者是用户允许的最小完整单元而非当前已实现能力。
- 浏览器缓存每个两小时数据批次的轻量展示结果；切换页面复用对应版本。两小时是数据覆盖范围，不是缓存到期后必须清空的 TTL。
- 不定时轮询指标。新的完整结果发布后，取得完整展示快照，再整体更新指标和图表，明确数据时间范围及生成时间。
- 推荐候选为 SSE 推送完成通知 + 按版本 GET 结果 + 浏览器缓存；直接推送完整轻量 JSON 也可行。此传输选型仍是建议，需与后端协商，不声称现有服务已提供 SSE/快照包。
- 页面首次打开/断线重连时对齐最近完整版本，弥补离线期间通知；不依赖只有在线才能接收的消息保存历史数据。重复/迟到通知按版本去重，不回退到旧版本。
- 缓存由 appid/model/run 或结果版本标识；内存覆盖站内切换，跨刷新缓存可采用 IndexedDB 等持久化机制，容量和权限边界后续确定。轻量包含总量、分位数、分箱、众数和质量/时间信息，不预装所有原始 prompt/IDs。
- 分析模块仅记录用户原则：异常触发或用户显式启动；无周期轮询；每 appid×模型×分析类型展示最近一次已发布的完整分析，标明分析时间及其数据范围。一个月前的结果继续保留，不因新监控批次覆盖/删除，也不冒充当前异常。具体 API 待分析器设计后确定。
