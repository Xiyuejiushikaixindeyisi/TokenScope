## 3. C01：合成输入与小样本运行控制

**代码范围**：新增本地合成输入生成器/规格（优先放`tests/fixtures/analysis/`与专用验证脚本）；修改`analysis_common/{execution_v3,runtime_v3,supervisor_v3,worker_v3,service_v3,sampling_v3}.py`，仅在需要时调整`source_preparation/sample_source`及V3类型导出。源选择仍走现有base/user_v2索引，冻结V2契约不改。

**实现步骤**：

1. 读取最新工作区，记录本批实际文件和候选摘要，保留他人dirty。核实DeepSeek/Qwen资产、revision、template、block与编码身份，缺失不得用假模型顶替。生成器固定种子/文本词表/长度填充，输出完整工具定义、合法历史、重算字段区间、输入SHA与用例角色表。工具数量与长system量级保持；不复制个人数据，不追求现场Token/收益一致。
2. 新任务默认一个discovery样本，关闭默认review选样；保留旧双窗产物读取。按稳定时间/索引取首个可用连续片段。拟采用300条、正文64MiB、prompt Token400万、单条8MiB/50万Token的工程上限，再与现有可用内存/模型校准取较小值。参数属于本方案待批内容，不是业务覆盖保证。允许依据实测向下收紧并记录，不扩大到全量。
3. 不在全量正文读取之后截断；元数据迭代/SQLite blob长度在前，正文/Token/JSON/编码在后。保留流式一致性检查，不为速度忽略源变化。单条超长提前排除，不截断正文假装有效。N足够小时N/N；无可用记录明确失败原因，不记成功。
4. 去掉V3任务/阶段/目录扫描的时间停止及deadline推导RLIMIT_CPU；保留耗时记录、CPU并发、主动取消、内存/磁盘保护、父进程退出回收。新profile明确无运行deadline，保留旧profile解析以读历史，不能用超大数字伪装取消时限。取消后清理等待不是分析时间上限。
5. 内存约束按raw文本、JSON对象、Token列表及模型固定开销计算，不能只按文件体积。复用准备阶段现有缩样重试，保证每次新attempt、释放前次对象和独立失败记录；资源不允许最小样本时给环境/超长单条原因，不能声称任何环境都不会OOM。

**测试门槛 C01-G**：

- 64条结构与关系可独立校验；同一参数两次生成摘要一致，输入中不含DEMO指标/指定recipe；负例与期望关系在规格中而非嵌入请求提示。
- `test_sampling_v3/test_sample_source_v3`覆盖N/N、自动缩样、同时间稳定序、字节/Token/单条限制、排除/连续片段、source变更拒绝。读取探针证明未选正文/Token未被物化，不能仅断言最终N。

## 4. C02：自动发现、精确改法与同样本参考

**代码范围**：`clock_worker_v3/evaluation_v3/sample_source/report_v3/diagnostic_store_v3`；`prefix_analysis/{clock_discovery_v3,session_clock_v3,prefix_findings_v3,candidates_v3,dynamic,timestamps}`只对实测缺陷作最小修改；必要的只读证据接入属于本批。复用`EncodingContext`与监控`PrefixLedger/make_strategy`。

**实现步骤**：

1. 用C01输入从正常prepare→diagnose入口自动发现，不传clock或recipe。优先确认现有L1已修能力；按角色/字段比较，不因无关历史序列排除。保持候选每请求前驱限制与总比较上限分开，不靠调大candidate_limit掩盖缺陷。保留必要L2/L3通道，L4/L5仍为差异证据。
2. clock只作用于自动发现所证明的合法块，保留外部模型/env英文日期/路径/记忆/tools/历史；标签内夹业务内容拒绝整块固定。BUS03短模板path保持普通L1，工具description路径为L3。before/after从实际应用plan生成，不能把对方原始路径当after。发现对数、匹配数、修改数独立计算。
3. 默认只评估当前一个样本，不强制B窗。baseline按统一实现校验/回放一次，记录源/成员顺序/编码/模型身份；复用只读Token或磁盘结果，不在内存缓存所有方案的编码。每条recipe独立after回放，使用相同样本及初始cache，逐项完成发布、释放中间数据。旧双窗报告仍可读，不自动重算。
4. 将累计读/编码工作量与驻留内存限制区分。按已去重方案数推导足够的执行计数与checkpoint容量，去掉旧plans=32等不相称的失败门槛；保留真实体量约束、取消和partial。不预挑正收益方案。plan/报告/行记录按单方案落盘，避免为每次发布重复堆积全量raw。若当前整体JSON不能容纳，使用已有受校验artifact引用保存明细，不另起通用任务框架。
5. 证据要支持原V2局部上下文，而不是全请求铺屏。分析阶段为每个可执行方案保存至少一组双边精确片段和改法片段，L4/L5按类保留至多3个展示代表例、总影响成员独立统计；超过证据容量须如实标partial，不让长raw挤掉所有L1证据。优先复用当前已封存请求/plan；需要按需读取时增加一个任务范围内的V3只读证据接口，按finding/group ID读取已保存内容，限制响应大小并校验成员/摘要，拒绝任意文件路径。GET不重新探测/编码/评估。
6. 状态区分discovery覆盖、单方案evaluation与任务状态：发现partial但单方案实算完整可展示该样本参考并注明限制；无对象、无修改、零/负、未评估/取消/失败不可混同。终态completed不应掩盖必需计算未完成。

**兼容边界**：若证据引用/单窗字段需增量V3类型，明确schema revision并兼容读取已发布report-3/双窗/旧profile，保留原schema身份测试；不能静默重写旧产物或让旧报告套上新完整性结论。V2冻结wire及资格仍按历史语义读。前端生成类型/能力校验随新V3修订同步在C03接入。

**测试门槛 C02-G**：

- `test_session_clock_v3/test_candidates_v3/test_prefix_repair_v3`覆盖五组结构、BUS03两类、斜杠/中文日期/text块/无关历史；clock无变化/不存在/非法/含业务内容负例不强报或扩大修改。未获真实片段的BUS05异常只能记为合成防御用例，不称已复现现场bug。
