## AC-MEM：大数据自动转小样本且可完成

**通过必须同时满足**：

1. 用户选择appid×模型/范围后即可发起有界诊断，不需要反复调sample_limit避开mem_limit。父scope很大时，正文批量读取/解析/编码前自动按元数据和资源profile缩小样本。
2. 样本仍按真实请求顺序、完整正文和统一编码计量分析；不截断正文冒充完整请求，不用稀疏拼接序列报真实缓存收益。自动缩样规则、原范围/入选N、排除和sample digest可见。
3. 支持环境下的大源验证及以下五组目标须完成小样本诊断和适用方案的样本评估，服务可响应、旧结果可读；OOM、容器mem_limit、内存杀worker、只返回“总数据太大/预算不足”均不能过关。
4. 总源校验是流式且内存有界，成本独立记账；小样本诊断不得重新加载全源正文/Token。如首版校验在目标数据量不能完成，保持问题OPEN，不能以解释文案替代修复。
5. 单条请求或模型固定开销超过机器能力属于不同边界，须给证据和清晰原因；不能以这种例外掩盖普通大源失败。资源profile具体值经V3B002校准，V3B007真实进程复测，不凭报告结束时内存数定预算。

证据：source/sample/profile身份、自动缩样前后计数、分阶段读取/解析/编码/比较/实际峰值、服务延迟、终态、容器/进程是否被kill、完整日志与复测。保护性kill只证明兜底触发，不算底线完成。

- 来源run/index/编码/资产/配置、sample keys digest、变换digest、评估ID和冻结报告身份可追溯。给足局部证据支持业务讨论，不向公开Git/外部服务发送真实正文。
- 业务说明：固定化会去掉实时日期/时区等时间感知，数值是离线理想缓存参考，不证明答案质量无损，也不等于实测TTFT/账单收益。实际采用由业务决定。
- 参考数字为真实结果，0或负值也必须显示并解释；不规定必须复制旧报告12.68–39.14pp，不降低校验来制造正收益。若不符合预期，记录确切适用/样本/候选/变换问题并修复或给真实结论，不能写虚假提升。
- B不足/无适用时可先展示A的已完成参考值，明确“尚无独立复核”；**该组完整业务证据门禁仍未关闭**。只有A/B完成或用户明确接受该组的具体复核局限，才能关闭该组。任何豁免须留用户决定，不能由agent代签。

默认“参考提升率”采用**命中率变化（百分点）**：`100 × (H_after / P_after − H_before / P_before)`，before/after各用自身P，不能将分母变化隐藏。另展示修改前/后命中率；若展示相对百分比必须另命名、单列公式。P=0记不可用，不能填0作为有效数值。
