### 可以纠正的旧判断

- BUS04未提供“模型名/路径被clock替换”的证据；当前finding指向clock，`session_clock_v3.normalize_clock`只替换合法目标块的内部。更精确地说，替换包括标签内的说明文字、空白和日期，不只是19字符日期；标签本身保留。
- BUS03 `/messages/0/content`的路径差异是`L1 + prefix-3.2`，不同于`L1 + clock-3.1`，不能按recipe版本将其误归L3。
- 英文日期位于env中，当前timestamp识别不支持该英文格式；无证据证明它在同一有效对照中变化，本轮不据此扩展英文日期修复。
- 五组均没有完整plan/evaluation，不能展示其真实参考率。新的报告称诊断峰值约0.36–1.56GiB、退出-15且forced=True，与旧报告262–275MB/exit0不同；分别保留来源，不能沿用旧数作全链验收。

### 尚存矛盾与重建限制

1. 统计表BUS01 28+3=31而总32；BUS02 19+3=22而总23；BUS05 4+2=6而总7。缺失类别未说明，不补造为L2或其他finding。BUS01 L4称135组，而`clock_discovery_v3.collect_clock`每rule上限128，可能混计不同cause，未证实。
2. BUS01给出的clock区间24156..24220长度64，实际这只是开标签加内部，到闭标签起点；正文示例整个块是80字符，不是报告所称82。取证脚本`ce+18`也与闭标签长度16不符。内层范围24171..24220与源码内部定位一致；所有合成区间必须重算，禁止照抄报告偏移。
3. path finding的after_fragments仍是另一条路径，与`dynamic.apply_recipe`执行删除槽的行为冲突；现成plan缺失。可使用“双边路径不同”作为构造依据，不能把第二条原路径当修改后结果。DEMO显示的是按源码预期删除后的局部文本，明确非现场实算。
4. CLOCK_TIME_UNSUPPORTED具体内容未提供；仅能设计额外“不支持日期”负例，不能声称复现BUS05那个原缺陷。报告对无L3原因、英文日期跨天变化、模型名/路径同base run静态的推测未得到双边全集支持。
5. LCP是完整编码输入的共同前缀，不等于system Token数；较高LCP不能推出历史变化更大。SQLite ledger行数不能证明修改是否发生，不能代替P/H/C或plan。phase deadline是monotonic绝对值，不能直接与elapsed比较或推出全部约300秒超时。
6. 报告骨架有占位字符串甚至tools中的"..."元素，不是可直接投喂模型的完整有效工具定义；填充文本/顺序/种子尚不足以原样复现。原始片段含个人标识，本地只使用USER0001等虚构标识，不传播姓名/邮箱。报告开头“尚未执行”是遗留说明，与正文取证事实分开。

以上缺口不阻止结构相似的合成设计，不据此承诺逐Token、原始数量或真实收益复现。没有原始片段的猜测不成为修复目标。

## 2. 合成样本规格（待批准后实现）

每组12条的主体：1–4为同模板clock按秒变化；5–6为同一clock值的重复对照；7–8保持system模板及工具相同、改变后续历史轮次/内容；9–10为独立工具路径对照（BUS04改用完全相同的无clock负例）；11–12为无clock且无动态变化负例。BUS03再加13–16短模板路径变化对照。上述负例是工程补充，不能称为全部来自现场。

1–8的clock外文本一致，自动发现仅需一对变化证据；固定化recipe应用范围可包含5–6两个未彼此变化但匹配方案的请求。因此“发现差异的对数”“适用数”“实际修改数”分开核实，不能把发现对数直接展示为影响请求数。负例另做独立仅相同clock报告，验证不强报方案；不能因混合样本存在有效recipe而要求其中相同clock成员一定不修改。

tools用完整合法function对象（name/description/parameters），前部采用报告所述名称，剩余采用稳定合成名称补足40/44或25个。clock对照内定义和顺序不变；工具路径对照仅description路径变化，其他字段不变。后续历史包含合法tool_call_id关联，避免错误工具序列成为干扰。

长system按分段构造：固定前段、模型名、env、固定中段、clock、固定后段。采用固定UTF-8文本词表和固定种子，各模板按Unicode字符数填充到目标长度/clock起点；记录生成器版本、参数、输出SHA、实际字节/Token数、每字段位置与关系。填充只模拟长度和结构，不复制业务正文；不能保证相同token分布或收益。若精确同时满足长度/起点冲突，以有效完整语法优先并披露偏差。字符串区间在解码文本定位，不能混作JSON转义字节偏移。

扩展对照独立于五组主样本：中文日期、text块、developer位置变化、无关历史结构、重复clock、非法日期、clock混入业务内容、异常标签；L2工具重排；L5同值JSON写法差异（含大整数）；不支持clock只记录原因不扩大替换。L5仅作原功能兼容，不能宣称现场五组均发现。

展示状态覆盖：微小正收益、零、负、无适用对象、未评估、partial。DEMO用示意数据展示这些状态；正式正常五组收益只能实算，不为匹配示意值调造结果。小正/零/负的数值展示可补组件受控状态测试；不能把组件注入状态当正常分析端到端实算。取消/中断场景用真实受控操作验证，不能给产品新增时间上限。

## 3. 端到端验收方案

| 层次 | 操作与可判定标准 | 必留证据 |
| --- | --- | --- |
| 来源与样本 | 新隔离state导入合成来源，锁定模型资产；五组N/N完整小范围，另做自动缩样。原CSV/state/旧结果不变 | 来源SHA、模型/template身份、父N/样本N及字节/Token、选样成员 |
| 自动发现 | 从普通分析入口开始，不预指定clock/recipe；五组clock对照检出；BUS03普通path与clock区别；工具变化走L3，历史不误挡L1；纯负例不强报 | 自动finding、双边请求和定位；原因与覆盖状态 |
| 改法 | 仅样本副本；clock内部替换，外部字符及其他字段保持；path另立方案，不拿路径B替路径A | 自动plan、应用前后diff、未改字段校验 |
| 样本参考 | 同一成员/顺序/模型/初始cache，完整before/after、P=H+C；不强制正收益、不要求复现15pp，不要求full | 实算P/H/C、pp、匹配/修改数、完整性；缺结果不填0 |
| 原页面 | 五组切换带动模型/报告/卡片；列表→详情→返回、刷新/深链接/历史可用；样本标签准确，无独立模块 | 实际API响应与截图、导航记录，浏览无分析POST |
| L4/L5 | 每类一张卡，最多3代表例；双边上下文/高亮，L5解码字符串大整数不失真，无收益伪装 | 比对DEMO及V2基线，定位与后端一致 |
| 数据与旧读 | 旧V2/V3、Token历史可读；不重算用户监控/搜索/MA，不改旧结果 | 隔离副本前后摘要、任务数和来源身份 |
| 大数据/健壮性 | 分离测试：按同样长请求结构扩展父来源（建议1200、12000阶梯），样本受条数及体量控制，完整链路结束；单条过长提前排除，无可用样本明确原因；无运行硬超时，主动取消有效 | 全阶段RSS及退出/缩样原因、读/解析/编码计数、完成评估。不能用12条页面演示代签mem_limit |

资源验证不增加产品时限；测试防挂措施仅用于记录测试失败。测试每次独立新attempt，先核路径再排他创建，保留失败证据。真正新版本E2E前按项目约定核旧TokenScope服务并停净、端口释放，新state/浏览器冷启动；当前DEMO仅file方式浏览，没有产品服务运行。

最终本机人工验收：用户打开实际前端，逐组检查问题、证据、改法、样本参考率和L4/L5，再检查负例与未完成状态。**实际页面应与获批DEMO在布局、信息位置、文案含义、交互上相符**；真实数值、数量、请求索引由分析产物决定，不要求像素中数字一致。发生展示设计变化必须重新提供DEMO并取得“前端展示审批通过”，不得用截图或自动测试代替用户验收。验收前保留DEMO摘要作为对照身份。
