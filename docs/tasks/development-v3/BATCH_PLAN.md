## 4. 每批agent执行协议

每批目录已提供[PLAN/ISSUES/TESTS/CLOSE](batches/V3B001/PLAN.md)四份初始文档。它们是待执行记录，不是已完成成果。启动某批前，只读该批依赖文档与所需源码/已有测试，不恢复旧六线或全量读历史。

1. **确认开始条件**：记录本次用户授权、依赖CLOSE、实际HEAD、他人dirty、设计版本和源码/契约/资产摘要；不创建其他会话或委派。未经授权不得实施。
2. **完善本批代码方案**：PLAN写清最终文件/函数、接口与数据流、失败路径、测试选择和回退边界；源码拆分调整可记录，范围/语义/验收门槛调整先回到评审。
3. **实现最小完整范围**：不借机清理无关模块；公共层先验证后被后端/前端消费。日志不含真实原文/secret。批内问题由本V3开发agent修复。
4. **验证并处理问题**：TESTS按T-ID填命令、candidate/fixture/profile身份、结果与证据；ISSUES区分设计风险/实测bug/环境缺失/业务约束，写复现、根因、修复、复测和关闭依据。失败修复后重跑受影响集合。
5. **闭环**：CLOSE列范围完成、设计符合性、必需用例、未决/阻断、变更候选、回退、下一批输入。必需测试未运行/失败/跳过、阻断问题未关、先决记录缺失，都不能CLOSED。
6. **增量记忆再推进**：当批完成或被阻断即更新[本线记忆](../../../memory/tasks/development-v3.md)，写batch状态、候选、设计变化、测试证据、issue/剩余依赖和下一步。长日志留artifacts，记忆用链接，不等七批结束才补记。
7. **进入下一批**：CLOSED且下一批前置满足后，按已获准的整体实施范围推进；授权覆盖整计划时不逐批重复索要批准。当前两项计划修订核对完成后即启动B001；后续依已授权范围按批推进。

状态约定：PLANNED → IN_PROGRESS → VERIFYING → CLOSED；遇阻记BLOCKED并保留实际已完成工作。最终批可LOCAL_VALIDATED等待真实底线证据，区别于CLOSED。CLOSE文档可持续更新但禁止提前签通过。
