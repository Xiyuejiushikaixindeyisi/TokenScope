## 3. req/s计算：统一窗口，保留突发与缺口

1. **主比较窗口**：优先使用原2026-10-20数据能证明覆盖完整的共同半开窗口`[start,end)`；分别报告pre/now，必要时再给连续合计。缺窗口不补造零流量；不同日期/不相交窗口只能分表说明。若只有历史数据，结论标“该历史窗口的流量”，不能称最新现网流量。
2. **时间事件**：优先同源可比的到达/请求时间；用户Trace可能只有`model_handle_start_time`（GF发出起点），这时明确称“处理起点req/s”，不能当GB到达率。可在MA上对目标appid与全部规格统一使用同一时间字段作主比较；用户Trace用于覆盖核对。若不同事件只能并列，说明排队/准入影响，不静默混比。列原字段样例、单位、UTC/北京时间及解析规则；历史CSV时间已确认UTC，仍核本次来源。
3. **计数集合**：给源行、有效时间、appid/模型/UUID、重复/重试/错误等计数及处理规则。输入JSON无效不自动排除一条有合法路由与时间的真实请求；不能用“可编码样本数”当全部流量。缺appid的MA请求仍可计入规格总量，目标归属未知单列。pre/now重叠或重复导出不得重复计量，也不能未经依据删除合法重试。
4. **均值**：`N / (end-start的秒数)`，包含完整可观测窗口内零流量时间。不用首末请求间隔缩短分母。同时报N、时长和覆盖；未知空档不是零。
5. **突发**：同一时间原点分1秒、60秒箱，给平均、P95/P99、最大req/s、峰值时间及完整可观测箱数（含零箱）。60秒箱rate=箱内请求数/实际箱秒数；尾部不足60秒单标，不伪装整分钟。给分位数算法；无完整覆盖时说明限制。
6. **合并**：A＋B先按时间箱相加再求峰值/分位数，不能把两个独立峰值或P95直接相加。规格总量、全部实例合计与目标子集要可对账；UUID活跃期和实例数变化单列，不用总量除以实例数代替真实逐实例负载。

请用表同时展示：A/B/A＋B；32K/64K/128K全业务；每规格每UUID；A/B在规格及UUID中的分布。表中均附时间字段、窗口、N、平均/1秒峰值/60秒峰值req/s、可得分位数、覆盖。保留实际峰值时段的简短时间序列，不只回全窗平均数。

## 4. 按“现网0731方案”承接两appid的初步判断

先核清用户所说部署方案在现场的具体含义，**不默认一个模型=一张卡，也不把10P5D当本次要求**：准确模型/模式/量化或精度、硬件与每节点卡数、P/D拓扑和实际总卡数、引擎/配置版本、最大上下文、并发/准入及缓存共享范围。32K/64K/128K是否同部署方案有证据就说明；配置缺失不推猜。仅访问已知授权路径，摘录时去除凭据。

寻找已有同模型/同硬件/同部署单元的实际观测或压测报告：记录负载输入/输出、缓存条件、SLO、观察窗口和证据日期。已有实例在某req/s运行只是观测点，不自动是上限；并发上限也不是req/s容量。目标输出负担或突发明显不同，则不能仅凭平均req/s较低判能承接。

最终给一个**初步、带条件的结论**：

如给“目标需求/已有观测或容量”的比例，明确分母是观测值还是已验证能力及适用条件，不把比例直接叫可用余量。不承诺缓存路由收益，不预先写生产重放脚本、实验参数或数据抽样方案。
