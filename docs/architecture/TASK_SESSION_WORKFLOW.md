dev6/F007本机联合、F007人工、统一审查与容器交付已完成；[B006结果](../tasks/monitoring/batches/B006/RESULT_20261028.md)绑定具体版本。华为现场尚待报告，不把本机验证当现场验收。

2. 后端负责启动失败排查、后端修复和必要复测；界面问题由前端修复；构建/镜像/Compose问题由打包session处理。模块责任不等于擅自远程操作权限。
3. 修复先在本地环境按影响验证，记录源码/资源/锁/S0/模型资产身份、问题、回归与回退。不得降低门槛或悄改契约。
4. 打包session统一审查候选及闭环，向用户呈现具体范围/结果/未决；有效明确打包授权后才构建、容器验证和归档。日常开发不用反复Docker重建。

6. 后端验收现场启动、合成功能、SSE/恢复/导出、浏览器能力和真实数据性能；每层单列通过/失败/未执行。启动成功不自动关闭B006 P5；用户人工验收不能由agent代签。生产CSV及正文只留现场。

## 设计、开发与契约

用户最新决定确定范围与授权；当前计划管步骤，测试文档管门槛，固定契约管接口，设计管技术依据，实际源码与证据只证明对应版本。B005.1已批准计划/设计/TESTS及S0保留作为维护依据，不重复申请已完成阶段审批。旧prompt与闭环批次是历史，不自动重新授权实施。

授权内按方案→实现→验证修复→问题/测试/结果→记忆推进，普通缺陷自行修复；重大目标、业务语义、接口、门槛或回退改变才与用户讨论。前端额外未知组件/类等重大变化依已有约定讨论。不能删断言换通过，不能把选择器失效直接称后端失败。

后端发布固定S0，消费者记录实际版本/SHA和接收状态；冻结文件不静默修改。接口变化写差异、兼容/迁移与影响，双方登记新版本。假服务、真实后端、真实浏览器、容器、现场证据分层，不互相替代。前端导出内存与完整性规则仍以批准设计为准，不因整理收紧或放宽。

## 入口、归档与协作

P0：AGENTS→CURRENT→本任务ENTRY；P1：当前设计、直接依赖契约、相关源码/测试；P2：按问题追依据；P3：[achieve](../../achieve/README.md)旧批次/旧prompt/日志。不全量重读项目，也不以默认清单禁止必要调查。

每批方案与结果要包含修改范围、依赖身份、测试、问题、偏差和回退。CURRENT只留路由，SESSIONS只留当前分工，历史过程移achieve；原始证据与冻结manifest不改，docs/archive既有快照原位保留。归档路径映射与导航性改动另存清单，不重算历史报告来冒充重测。

共享工作区修改前核对最新状态，按模块责任保留他人工作。文档交接不等于实时通知；不自动创建/唤醒会话、委派子agent、发跨会话消息或设置自动化。个人Git不用PR，按[Git流程](../operations/GIT_WORKFLOW.md)操作；禁止全局reset清理共享修改。
