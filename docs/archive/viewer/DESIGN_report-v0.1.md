## 分析报告展示 v0.1（用户已批准展示方案）

2026-10-26 依据用户投递的 [PrefixLens 页面片段](../../../evidence/source_drops/prefixlens-ui-demo/prefixlens_demo.html)提出。用户明确：具体分析内容及是否具备展示条件由分析后端决定，前端只提供交互呈现能力。方案批准后已实现首版离线 HTML；尚未定义正式 HTTP API 或启动分析算法开发。

### 1. 已读材料与采用边界

原文件 SHA256：`324f2bc93880e77bb6fb6bb159be2478bcc0995d69a250272047b79182487284`，15,018 字节。含诊断与 Traffic Replay 两部分；无配套 CSS/JS，夹有 Markdown 围栏，属于页面结构/文案参考，未验证可运行交互。示例收益与“已由后端验证”的文案不能替代实际后端结果。

借鉴诊断部分的摘要、原因横条、模板段位置、建议条目和展开定位；有限容量、淘汰策略、TTL、TTFT 及浏览器 Worker 回放不进入本次方案。不把示例的六段 GLM 模板、原因名称、风险等级或数值固化为 TokenScope 通用事实。

### 2. 页面结构

沿用现有导航与浅灰蓝/白色界面，增加“分析报告”入口。监控异常旁的“查看报告”仅在已有报告可关联时出现。报告列表按已存在的模型、appid、分析类型、状态筛选；选择模型是读取该模型报告，不将旧报告换 tokenizer 后重新解释。

详情顶部保留返回入口、报告类型、模型/appid、来源文件/运行、报告时间与状态。主内容依次为摘要 → 发现列表 → 选中发现的证据/建议/评估。发现使用紧凑行，包含后端提供的标题、类别、影响范围和验证状态；默认遵从后端排序，前端不推断严重性或排序分数。长证据在宽内容区阅读，短记录用抽屉；不层叠弹窗。切换发现保留筛选和列表位置。

两类报告共享骨架，内容组件按后端实际提供的信息选择；摘要字段和数量不固定，不为凑齐卡片虚构数据。

### 3. 低理想命中率报告的可选组件

| 后端提供的内容 | 前端呈现与交互 |
| --- | --- |
| 原因类别及影响量 | 横向条形图与数值；可筛选关联发现，不自行汇总重叠原因 |
| 模板语义段及断点分布 | 按报告实际顺序绘制位置条；无映射时不画虚构六段图 |
| 请求对、模板后文本及断点坐标 | 并排差异片段、定位跳转、展开上下文；区别 LCP 差异位置与可复用块边界 |
| 原字段路径与来源映射 | 在原请求/模板后视图间切换；路径类型及坐标单位以报告为准，未知不猜测 |
| 修改建议和前后示例 | 文本建议与对照视图；仅查看/复制，不直接改生产 prompt |
| 单项或组合评估结果 | 展示基线、评估后值、百分点、重算量及评估范围/状态；只选择已有评估结果 |

没有收益结果则显示“未提供评估”，不计算估计提升；组合方案仅在后端提供相应组合结果时可查看，不把单项提升求和。仿真收益已验证与业务语义安全已验证应分别标注，前端不把前者变成后者。

### 4. Token 分析报告的可选组件

| 后端提供的发现/证据 | 可选择的呈现 |
| --- | --- |
| 请求长度或总量异常及比较依据 | 当前值/参考值和分布对照，明确输入、重算、输出等口径；没有参考值不画比较 |
| 工具返回或其他来源贡献 | 横向贡献条、内容片段与请求定位；不完整映射保留未知部分，不凑满 100% |
| 工具失败和重试记录 | 有序事件列表，显示参数、错误及变化，重复长文本折叠 |
| 可靠 session/turn 关联的调用序列 | 步骤列表/上下文变化；仅有消息顺序时标为请求内历史，不称完整调用轨迹 |
| 工具重叠的分析证据 | 功能、输入、返回或实例的并排对照；不根据名称相似度自行判定冗余 |
| 建议与评估 | 复用建议/对照组件；缺少收益时只呈现文字建议 |

这些是可承载内容，不是要求后端首版全部实现。报告的事实、假设、原因判断及可信度来自后端；前端不执行判因、不计算 Token 归因或重放。

### 5. 可用性与空态

报告/组件区分未生成、处理中、完成、部分结果、失败和不支持等状态，名称在接口设计阶段共同确定。整体无报告显示明确空态；可选图无数据不占大块空白；已有发现缺少细节时就地说明“未提供定位/建议/评估”。缺失值不显示为 0，隐藏或禁用不可用动作并解释原因。没有发现也不自动写成“系统无异常”，需保留分析覆盖范围。

前端需要的最小展示信息类别是报告身份/范围、状态/能力、摘要、发现、证据、建议、评估及关联记录引用；这只是供后端共同讨论的输入清单，不冻结字段 Schema。能力与数据必须一致后才启用对应控件。页面访问、筛选、展开均不隐式触发分析或重算；显式启动/重新评估等操作留下一阶段协商。

### 6. 视觉与下一步

复用当前蓝色选中态、白色内容区和浅灰蓝背景；正文保持清楚对比。差异仅局部强调，同时用文字/符号区分；避免整篇 prompt 染红、默认铺满代码或重复堆指标。每个发现优先一张主图，详细证据按需展开。

用户已批准上述展示方案，当前 HTML 已增加报告入口与详情，原冻结监控基线保持不变。具体业务内容仍由两个分析后端确认；下一阶段共同设计监控前后端交互、数据读取和流畅性。
