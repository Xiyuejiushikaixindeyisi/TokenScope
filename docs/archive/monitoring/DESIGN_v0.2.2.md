# Token 监控设计

版本：v0.2.2-discussion，2026-10-26。状态：用户确认布局 txt 作为背景，主结果采用固定、可配置的顺序 prefill 规则；全合法边界保存状态单列理论情景。已补充读写回放步骤与组级证据草案。具体 profile、质量策略和告警规则继续讨论。未启动实现、未达到 fork 交接状态。

依据：本会话用户最新功能输入及追问答复优先；[V1_SCOPE](../../requirements/V1_SCOPE.md) 保留总体背景。源码事实见 [首轮调研](../../research/implementations/MONITORING_RESEARCH_2026-10-23.md) 与 [Ascend page/编码调研](../../research/implementations/MONITORING_RESEARCH_2026-10-26.md)，固定入口与测试见 [当前 CODEMAP](../../tasks/monitoring/CODEMAP.md)。下文明确区分已确认要求、设计建议和待核实事实。

## 已确认的功能范围

- 第一版由用户提供带表头 CSV，不主动采集，不打通完整线上链路；每个目标模型一个 CSV。
- 目标模型：Qwen3.6-27B、DeepSeek-V4-Flash-0731、GLM-5.2。用户说明镜像版本 0.23.0、MTP 默认开启、block size 默认 128；启动参数暂不可得。镜像摘要、实际源码补丁、模型 revision 和最终生效配置尚未核实。
- 输入列：`hash_id`（请求唯一标识）、`appid`（租户）、`model_handle_start_time`（模型开始处理时间）、`completion_tokens`（输出长度）、`request_input`（未套模板的 OpenAI v1 格式完整 JSON 请求体）。
- 用户已确认 request_input 是 GF 网关转换后送往推理服务的请求体；模型输入均为纯文本，包括工具定义、调用与文本工具返回。无需复现 GF 转换；推理服务侧模板默认值/覆盖参数仍需绑定配置。流式输出不改变这一输入边界。
- 按 appid × 模型统计；不同 appid 独立缓存，不计跨租户复用。每个 CSV 从空缓存开始，不继承上一个窗口。
- 理想命中假定 HBM 无限，不发生容量淘汰；保留目标引擎与模型的缓存合法性约束。
- 用户已接受前一请求的可缓存输入立即对后一请求可用；只回放 CSV 可见输入前缀，不由 completion_tokens 猜测生成 Token 或补造缓存键。
- 模板前计量对象已确认是 `request_input` 完整原始 JSON 文本，包括字段名、标点、空白及参数。
- 第 4/8 项只统计输入侧需要计算的 Token；输出 `completion_tokens` 单独汇总。
- 每两小时分析两小时数据，必须在两小时内出结果。万条以上请求是规模输入，不是完整性能测试负载定义。
- 阈值触发报警信号，作为分析器启动开关；页面访问不启动计算或分析。
- page 分配及复用行为以 vLLM-Ascend 版本代码/PR 为主要依据；vLLM、SGLang 作参考。已接收用户的缓存布局 txt，原件和逐项核对见 [布局材料核对](../../research/implementations/MONITORING_LAYOUT_REVIEW_2026-10-26.md)；材料未明确部分前缀注册、恢复和 COW 算法，不将其自动升级为已定增强方案。
- 后端提供总量、命中率和 P50/P80/P90 的权威值，前端负责图形和交互；长度证据采用全量轻量信息、按需生成详细来源映射。
- GDN 等状态缓存的主结果绑定固定、可配置的顺序 prefill 规则；每个合法边界都保存状态的方案单列理论情景，不混为部署规则已支持的能力。具体每步预算尚未确定。

| --- | --- |

| 输出量 | 单独汇总 completion_tokens，不混入输入重算量 |

## 计量与可追溯性

公共语义集中在 [监控计量契约 v0.2 草案](../../contracts/MONITORING_V0_2.md)，这里只记录采用理由和开放问题。

建议对请求 i 定义 J_i 为原始 JSON Token 数，P_i 为模板后输入 Token 数，H_i 为引擎规则下可复用输入 Token 数，C_i = P_i - H_i。分组理想命中率建议采用 sum(H_i) / sum(P_i)，而非请求命中率的算术平均或块数比例。空分母输出不可计算状态，不伪装为 0%。该公式尚待讨论确认。

模板前统计必须保留 CSV 正常解码后的原字符串，不能 parse JSON 后重新 dumps，也不能把 CSV 外层引号/转义算进请求体。模板后则解析整个请求并正确传递 messages、tools、思考模式及相关模板选项；不能把整个 JSON 包成一条 user 消息。

三个模型的 tokenizer、模板/编码器、默认模式均需绑定 revision、文件 SHA256 和有效配置。模型名或 CSV 文件名不能代替版本身份。当前取得的是公开参考版本，不是现场已经核验的文件。

建议保存每请求 J/P/H/C、completion_tokens、时间和原始行定位，以及来源文件摘要、编码配置身份、缓存规则身份、质量状态。全量轻量证据与详细映射按下方约定分层；Token IDs/块键的实际存储格式和保留期继续设计。保持监控维护一套计算口径，供两类诊断复用。

## 三模块边界（用户已确认）

| 模块 | 责任 | 交付给下一环节的必要信息（字段名尚为草案） |
| --- | --- | --- |
| 基础转换 | 分批预读取、CSV/JSON 校验、保留原始 JSON、模型模板适配、Rust 批量编码、受控并行 | 请求定位/时间/租户、模型与编码身份、J/P、模板后 Token 序列、轻量来源证据及质量状态 |
| Prefix cache hit 仿真 | appid × 模型/profile 内按时间回放，维护前缀键、各组 page/状态可用性、共同恢复边界 | H/C、命中边界、规则身份、必要的组级候选/限制边界和检查点事件；它们是事实记录，不是原因诊断 |
| 数据统计 | 同一有效集合的总量/请求数/分位数，三组长度排序数据，基线比较、规则判断与报警信号 | 后端权威统计及图数据、运行质量、结果定位、带规则身份的分析触发信号 |

三模块共享版本化的运行清单；不是按三个模型复制三套流水线。模块可独立验证和重放；错误不跨模块静默转为零。图形布局和诊断报告不在本任务细化。

建议过程性接口为 `encode_batch → replay_partition → aggregate_and_evaluate`，以及供诊断复用的 `explain_encoding(request_ref, encoding_profile_id)`。这里定义能力和数据流，不冻结 Python/Rust API、RPC 或文件格式。

基础转换完成并行处理后，必须恢复租户内的回放顺序。大文件未按时间排序时需有稳定排序/外部排序方案；读入 chunk 不是模型 prefill chunk，两者不能混为状态保存边界。

## 理想缓存仿真：初步方向

建议编码并行、仿真按 appid 内时间顺序进行，同时间以原始 CSV 行号稳定排序。图表排序在仿真完成后进行，不能用长度排序改变回放次序。

仅有开始时间，无法恢复真实计算完成/通信时刻。已采用“前一请求可缓存输入立即可用”的理想化顺序回放；它衡量约定输入范围和缓存策略下的无限容量复用，不声称还原真实并发服务、输出缓存或窗口前热缓存。C 是仍需处理的输入 Token 数，不是跨模型可直接比较的 FLOPs 或延迟估计。

用户提出按 page 复用方式分类，设计采用“缓存规则配置”（cache profile）表达，而非只按模型名字选择一个 block size：

- 普通/full-attention 或 MLA/DSA 路径：连续前缀块匹配、整块边界、最后 logits token 重算、MTP 退块。GLM-5.2 具有 DSA，不能仅凭名称视作普通 dense attention。
- Qwen3.6-27B：GDN 状态与 full-attention 混合；需要状态检查点及 attention 共同可恢复的边界。0.23.0 Ascend 下 1536 是有条件可推导的有效块，不是所有配置固定值；没有发现“关闭某个 hybrid 开关必然变成 1536”的充分证据。
- DeepSeek-V4-Flash-0731：SWA、C4/C128 压缩缓存及状态；0.23.0 Ascend 的有效逻辑块需乘压缩比例，再取组间共同对齐。默认 128 的相关配置可能达到 16384-token 命中粒度；不能套用其他后端的 256。

| 仿真通道 | 可复用的机制 | 当前设计边界 |
| --- | --- | --- |
| 普通链式前缀 | 全历史 KV 的连续块匹配，按有效逻辑块处理 MTP/尾部重算 | GLM-5.2 等目标先核对其 Ascend spec、完整输入状态和额外缓存身份，不能仅凭 MLA/GQA/DSA 名称宣布等价 |
| V4 粗粒度 | CompressAttentionManager 已直接使用链式键/连续匹配 | 支持研究将共同粒度折叠为单 B 的快速路径；须有 SWA/状态恢复条件及 MTP 策略，未证明等价前标为简化情景，不冒充部署仿真 |
| V4 增强 | 部分页前缀、状态保存/复制、跨组恢复边界 | 独立通道；用户布局 txt 已核对，具体部分页/状态算法仍需共同设计；不以 HiCache/HiSparse 名称代替能力定义 |
| Qwen/GDN 等粗粒度状态缓存 | attention 链式前缀 + 已物化 recurrent checkpoint 查找 | 即使不启用细粒度功能，也不能简化成“每 B 个 Token 都有状态”；需明确 align/checkpoint 调度策略 |
| Qwen/GDN 等增强 | 匹配单位与物理页分离、部分状态、共享前缀 admission、COW | 独立通道；区分尾状态、二次发现共享前缀后的 admission 和 all-mode，不能合并为一个开关 |

Qwen 同系列或 KDA 模型只有在 page 布局、状态含义、保存策略、恢复条件一致且有证据时才复用对应 profile；名称变化本身既不必复制模拟器，也不证明兼容。这里不预先断言未核实模型的结构。

缓存 profile 至少应区分：版本/补丁与角色、是否启用前缀缓存、各组物理 page 字节/布局、存储 slot 与原始 Token 换算、hash/match unit、共同恢复对齐、状态 admission/retention、SWA 所需范围、MTP 读写规则、CP/通信边界和证据等级。

物理 page、逻辑 Token 粒度、hash 粒度、可恢复状态边界分开记录；不复用一个 `block_size` 字段表达所有量。page 的形状/共享复制/传输会影响是否可恢复，因此要建模这些条件；当前不分配真实 KV tensor、不仿真带宽/拓扑时延。无限 HBM 与立即可用不消除状态存在性约束。

本轮源码与 PR 核对得到的版本限制：

- Ascend 0.23.0 压缩组读写已考虑 compress_ratio。#10350/#10355/#10440 的 V4 部分页提案关闭未合并，不作为现有功能。
- Ascend #16013 已合并的分段 page 复制修复是后续主干能力；#14468 的 v0.25.1rc admission 修复、#16528 的 PD+MTP 适配仍未合并。vLLM #46384/#37898 已合并不等于现场 Ascend 具备完整链路。
- 当前主干 MTP 回退可依角色变化，与 0.23.0 不同；不能统一减 128，也不能静默使用最新策略。

规则来源未齐时，J/P/请求数仍可单独形成有质量标记的结果；H/C 不猜测为零。候选简化情景应与经核对的 profile 结果分开，比较或触发告警时不能混入同一基线。具体准入/失败政策仍需收敛。

当前先建立配置事实与规则，不将未知模式默认为已支持，也不将 HBM 无限解释为所有本来不会保存的 GDN/压缩状态都可恢复。MTP 的退块位置、大小和次数依照对应版本各组 manager/coordinator，不能对最终命中统一减 128。

### 从布局材料得到的仿真细化建议

缓存仿真模块内部划分为规则解析和逻辑回放两层，产品仍保持已确认的三个模块：

1. 规则解析将固定版本的 spec、有效参数和补丁转换为各组的原始 Token 覆盖量、存储条目数、page 字节、匹配单位及保存/恢复条件，保留原值和单位用于追溯。Ascend 压缩 MLA 的 B 不能直接和 vLLM 同名字段比较；状态 slot 也不能冒充输入 Token。
2. 逻辑回放在已存在的缓存上查询各组合法恢复边界，寻找共同边界 H，计算 C=P-H，随后根据当前请求的计算与状态物化策略更新缓存。不能把本请求新建的检查点算成该请求此前已命中。

用集合表示，H 是满足尾部/MTP 条件的各组合法恢复集合交集中的最大边界。实现可使用版本 coordinator 的下降搜索；不能只取各组最大命中长度的最小值，因为状态快照并非可以任意截短。参考 [明确标注的边界示例](../../contracts/examples/monitoring-v0.2-recovery-boundary-illustrative.json)。

集合表达用于说明共同恢复的合法性；复现具体版本的 profile 还须遵守该 coordinator 的实际候选/回退顺序。若其保守行为与更宽松的集合上限存在差异，单列比较，不擅自把更大的 H 当作该版本仿真结果。

在无限容量假设下，可省去真实 KV tensor、pool 容量预算、因容量不足的淘汰和 free queue 排序；仍保留组级键、必要 SWA 尾部、检查点物化/admission/retention、COW 后有效性以及角色/MTP 限制。原文的 ledger 思路用于模拟这层语义，而不要求复制所有物理分配器逻辑。

本轮核对发现，目标公开 Flash-0731 配置是 43 个主干层，不能直接采用 txt 的 61 层/243 份 cache/5 group。固定 0.23.0 allocator 也不能直接套用材料中的 block-major packing；Ascend 按 ratio、page-size 和 slot 的特殊分组/分配见 CODEMAP。group 数量、worker tensor stride 仍需部署配置证据，不因两档 page 大小就推定具体布局。

以上是依据源码提出的监控抽象；增强 V4 的 checkpoint 位置、部分页键、恢复所需状态和复制语义还未冻结，不以布局说明替代该设计。

### 请求回放步骤与主结果口径

用户已确认固定 prefill 规则作为主结果。主结果衡量指定缓存保存/调度策略下的无限容量输入复用；不对所有可能调度取最大值。另设的全合法边界保存情景仍遵守对应编码、page/恢复单位和 MTP 约束；合法边界未被证明时，不输出貌似精确的理论值。

每个 appid × 模型/profile 分区维护一份逻辑缓存账本，建议每条请求依次执行：

1. **读取既有状态**：依据模板后 IDs 和缓存身份产生链式前缀键，仅查询之前请求发布的内容。保存输入长度、P−1 上限及 profile 身份。
2. **确定共同恢复边界**：按组查询 attention 连续前缀、SWA 必需尾部、已物化状态；由固定版本的 MTP/peek/对齐和协调规则得到 H，计算 C=P−H。新物化状态不回写本次 H。
3. **规划并回放剩余 prefill**：从 H 开始，使用配置中的每步 Token 预算和拆分规则，逐步记录哪些内容/状态完成；不把 CSV 读取批次或编码线程任务当作引擎步骤。
4. **发布允许保存的内容**：每步只注册已完成、非 null、满足完整度/保留策略的键与状态。必要 COW 语义必须保持旧前缀不变；未物化、中途失效或部分页不满足规则的内容不发布。
5. **结束请求**：释放请求私有活动状态；无限容量下已注册且仍有效的缓存保留。随后才回放下一请求，符合已确认的立即可用假设。

仿真只执行逻辑账本和版本化规则，不执行模型前向。即使没有并发，也须保留请求内部的步骤，因为它们会改变未来请求能命中的状态。输出只有 completion_tokens 数量，不用于补造 decode 检查点。

profile 补充 `prefill_policy`：规则版本、每步 Token 预算、拆分/发布策略和证据等级。参数修改产生新的 profile 身份，不能沿用原基线。固定预算如何选取、配置校验及最终字段类型仍待收敛；不将未知现场预算静默填成真实配置。

每请求的轻量缓存证据建议包含：最终 H/C、回放顺序、各组候选与最终边界、参与约束的 page/match unit、需要的状态或尾部是否存在、检查点发布数量及可重放轨迹引用。详细逐步/逐块轨迹可按同一规则重放生成；不要求全量输出真实 page tensor 或数值状态。这里记录的是机制事实，不提前给出两类诊断的根因分类。

### 快速路径与增强能力的准入

V4 单 B 快速路径必须证明与组级回放等价：压缩链连续、共同边界的 SWA/状态均可恢复、retention 不产生空洞、角色及 MTP 投影一致。LCM 只是必要对齐条件；未证明时保留组级路径。

增强 profile 至少需给出：匹配单位与物理页的关系、部分页有效范围、边界所需完整状态集合、压缩残留/相位的处理、恢复后的可写副本隔离及状态发布时间。V4 与 GDN 可共享接口概念，不能共享未经证明的保存规则。未核实能力标为 unsupported/unverified，不静默换为普通链式仿真。

源码事实与 8 个隔离函数案例见[回放规则推导](../../research/implementations/MONITORING_REPLAY_RULES_2026-10-26.md)。SWA 的 retention=None/0/正周期影响可查询尾部；GDN align 模式受 prefill 终点影响。已确认的固定规则使结果可重放，但不是恢复真实调度的证据。

## 长度证据分层（用户已确认）

全量保留精确 J/P/H/C、原始行定位/文件摘要、模型/tokenizer/模板/模式身份、prompt 与 Token IDs 摘要，以及经验证模板适配器产生的特殊 token 区间和轻量来源索引。保存原 CSV 或有摘要的稳定请求源，保证后续可重放；具体保留期和压缩格式待定。

详细映射按需由监控共用编码接口产生：JSON 字段/工具等来源 → 渲染后的 UTF-8 byte span → Token 区间。细查可以采用带 offsets 的编码路径，但必须与全量快路径产生相同 Token IDs/摘要；不一致时报告失败，不向诊断提供伪精确归因。原始 JSON 也须独立建立来源账本，不能先重序列化。

Recipe 的 special_ranges 只证明特殊 token 边界，普通段仍混合模板文字、正文、工具格式等；encode_batch_fast 不计算 offsets。Qwen/GLM 模板的特殊 token 来源和 span 采集也需做适配/验证，不能用正则搜到同名字符串就称为模板插入。未取得的细节返回 unavailable/partial，而不是虚构映射。

P-J 同时包含 JSON 外壳/参数省略、转义/空白/工具格式改写、模板插入、思考内容处理和分词边界变化，因此称为“原始 JSON 与模型输入的长度差”，不称为纯模板开销。详细来源边界被同一 BPE token 跨越时单列 mixed-boundary/unknown，账本应守恒，不能将每字段独立编码结果相加充当精确分解。

监控提供这些转换事实与复用接口；内容异常判断、根因分类和优化建议由 Session 3 设计。按需细查不由页面访问自动触发，也不成为每两小时全量运行的必经成本。

## 性能方向与代码要求建议

候选流程：CSV 分批读入及校验 → 模型适配/模板渲染 → Rust tokenizer 批量并行 → 每租户按时间回放 → 聚合、三组排序/分位数 → 报警及结果落盘。

- Qwen/GLM 优先评估官方 tokenizer 配合成熟 Rust tokenizers 内核，不先重写 BPE。DeepSeek 优先评估 deepseek-recipe 的模型专用转换和 Rust 编码；需对齐 0.23.0 的 deepseek_v4 服务编码，不因其更新就直接替换。
- CSV 按批次/chunk 处理；单条 prompt 只能沿编码器保证等价的边界分段，不能任意按字符切割后拼接 Token IDs。
- 一次加载复用模型编码资产；限制嵌套进程/线程数量，避免过量并行。缓存相同编码输入时保留请求次数和时间语义。
- 批次同时限制请求条数及文本/预计 Token 字节量，用有界队列提供背压；单条超长请求要有单独资源策略。执行编码可复用不等于删除重复请求；hash_id 去重政策另定。
- 聚合与缓存仿真不依赖 GPU 推理；不能靠运行完整模型取长度作为常规路径。
- 两小时预算覆盖读取、JSON 计量、模板计量、仿真、排序、报警和持久化。实际 SLA 必须用 CPU/RAM、文件字节数、请求数、总 Token、最长请求和模型混合负载实测，不能引用别处的 tok/s 当验收结果。
- 原始 JSON 计量与模板后编码是两份工作量。若两者需编码总量为 T，光编码的必要平均吞吐已是 T/7200；还需为其他阶段留预算。

这些是候选实现方向，不是已批准依赖、固定进程数或已验证吞吐。

后端统计从与告警一致的有效集合产生精确总量和 P50/P80/P90。三张图各自按长度降序、同长按稳定请求身份排序，提供完整点数据或可分页读取的完整序列；图形展示由前端实现，不能靠抽样替代“一请求一点”的数据要求。分位数算法仍待确认，不能由前后端各选一种。

## 告警与分析器边界

用户已确认阈值报警触发分析器。建议理想命中率采用下穿阈值/相对下降，Token 总数和长度分位数采用上穿/相对上升；规则逐项配置方向，不能所有指标都用“超过”。

告警建议携带 appid、模型和窗口身份、指标/阈值/比较方向、观察值、规则版本及结果位置。低命中路由到前缀分析，输入长度异常路由到长度分析；请求数或总量上升是否启动何种分析需讨论，不能把正常业务增长直接诊断为请求长度问题。

绝对/相对阈值、基线定义、最小样本量、防抖、重复执行的事件去重和阈值配置入口仍待讨论。本任务只设计信号及触发边界，不提前实现分析器内部逻辑。
