# B006 交付准备方案

1. 白名单构建上下文：后端src、锁文件、验证脚本、三模型固定编码资产、实际API与运行/验收说明；不包含真实CSV、状态库、凭据、研究仓库或未确认的前端。前端版本与是否纳入需用户最终确认。
2. CPU linux/amd64镜像包含Python3.11和全部锁定依赖/词表，运行无需联网或GPU。基础镜像必须digest固定，依赖require-hashes。Compose限定8CPU/32GiB、专属持久化目录、只读输入；启动健康检查和ready区别。
3. 构建脚本先校验批准凭据/B005报告/来源摘要，再一次性构建镜像、镜像验收、docker save和代码包/执行prompt/校验manifest；日常修正先本地复测，只有必要最终变更才重构。
4. 本轮只做脚本静态、白名单/无批准拒绝测试；不调用docker build/save，不创建交付tar。当前Docker CLI未检测到，构建环境准备列为执行前置。
5. 用户明确同意并确认前端范围后，执行离线容器回归再形成交付。现场agent校验摘要、加载、专属目录启动、三模型合成首次验收、重启；真实绝密CSV仅在现场分析。M11/M12和旧内核兼容性必须实际回传脱敏结果，不能由本机通过替代。
回退：专属Compose项目停机后使用上个release及兼容状态备份，不down -v、不prune、不删除业务数据。
