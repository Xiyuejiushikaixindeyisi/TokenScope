## 待讨论的展示提案

统一顺序：结论 → 影响范围 → 可定位证据 → 修改建议 → 评估结果。报告列表用于发现问题，完整详情用于阅读长证据；摘要保持少量指标。每个发现说明观察事实、推测原因和验证状态，原始 JSON/完整 prompt 默认折叠。

LCP：展示模板后共用前缀、首个不同 Token 的局部对照、与可复用块边界的区别，必要时定位回原始字段；建议给修改前后例子。收益列出同一数据集/规则下的前后仿真值、百分点和重算量，未重跑不填预计提升数；多个建议收益不直接累加。

Token：先分辨请求数增加、单次输入增长、重算增加、输出增加，再展示相应发现。工具返回长度用横向贡献条，失败重试用有序事件列表，循环用调用序列，工具重叠用功能/输入/返回并排对照。不将调用多或名称相似直接判为 bug；不使用无证据的精确归因或置信度百分比。

CSV 当前只有请求级身份/时间和请求体，缺可靠 session/turn 边界。可观察请求内携带的消息和工具记录，但不能把相邻 CSV 行当作同一会话。历史记录在多个请求中重复携带，不能简单累计为实际工具执行次数。工具失败需要结构化状态或可核查错误内容；工具功能重叠需语义和行为证据。跨调用序列仅在可靠关联数据存在时展示；本次讨论不自动扩大 Session 3 的实现范围。

Token 来源贡献复用监控提供的映射；覆盖不全显示未知部分，不独立分词求和后宣称精确。TraceLab 的实际缓存/超时研究不直接套到 TokenScope 无限容量、立即可用的理想命中规则。

视觉提案：保持现有浅灰蓝背景、白色内容区与蓝色选中态，正文保持足够对比度；证据局部使用低饱和强调色和文字标签，红色仅标明确错误。每个问题一张主图，减少重复卡片和默认展开的长代码。具体布局仍待用户讨论和 PrefixLens DEMO。
