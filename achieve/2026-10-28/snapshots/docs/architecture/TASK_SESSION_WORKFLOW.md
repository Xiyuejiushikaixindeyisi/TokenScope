### 前后端交接与接口变化

1. 后端发布固定S0；前端在自身CONTEXT登记实际采用的版本/SHA、接收时间和仍有的疑问。生产方提供与消费方确认分开记录，不替对方标记通过。
2. 双方在已有授权内并行开发，各自维护模块与问题。前端假服务消费固定字段；后端按同一Schema实现。不能为赶进度各自改接口。
3. 后端S5完成后，在自身RESULT/交接中提供启动命令、地址、代码/契约身份、实际OpenAPI、合成数据入口、验证结果和遗留问题，标记backend_ready_for_joint。
4. 前端F006在自身RESULT提供源码/构建命令/锁文件/静态资源摘要、采用契约、测试与问题、回退方法，标记ready_for_joint；这不等于release_ready。
5. 跨模块问题由发现方在本模块ISSUES记录ID、双方版本、预期/实际、最小合成复现、影响及建议责任方，并链接到交接。修复方记录修正/回归证据，发起方复核后关闭；用户不负责逐字段转述。
6. 共享契约由后端维护；影响消费方的变更先记录差异、兼容性与迁移办法，再按既定重大变更规则讨论并由双方登记新版本。冻结文件不静默改写。会话不自动实时同步：每个步骤开始/交接前主动读直接依赖的最新记录；未获明确授权不跨会话自动发消息或委派agent。

### 开发约束与状态门槛

- 当前batch/步骤先写具体修改范围、依赖版本、测试与回退，再编码；每步把问题、命令/退出码/证据、设计偏差写入父batch五文档的对应小节，避免为每个微步骤再建一套文档。批完成增量更新记忆，CURRENT只保留路由。
- 在已授权范围内，测试通过、问题闭环、依赖满足才进入下一步；普通实现选择和修复无需反复批准。遵循各会话用户额外指定的暂停约束，不用通用规则覆盖它。
- 不能把失败检查标为通过、降低门槛或跳过必须验证。目标/接口/数据口径/验收/回退发生实质变化时讨论具体影响，不以文档数量增加审批次数。
- 本地环境开发；复用唯一编码/计量/仿真实现，GET只读已有成果；不启动增强hybrid、诊断或Agent的新范围。只生成固定种子、每模型5appid的泊松合成数据，本机不索取生产CSV。
- 测试证据分层：契约/假服务、真实后端、真实浏览器联合、容器、V100现场；前一层通过不能代替后一层。每份报告绑定候选代码、配置、资产、数据与环境。
- Session 1接收双方成果后统一真实前后端E2E、健壮性、恢复/导出、性能与设计对照；未通过先本地修复并回归，不进入打包。
- 联合通过后向用户展示具体候选范围、验证结果、遗留风险并询问打包意见。明确同意后才构建包含环境和前端资源的Docker镜像及交付包，不将每次改代码变成镜像重建。
- 容器验证通过才归档代码包＋镜像＋执行prompt＋版本/校验清单；华为机agent预检、加载并启动完整服务，现场功能/兼容性/每文件两小时验收另记，未完成不关闭B006。

### 文档权威与冲突处理

最新用户决定确定范围与授权；当前batch PLAN管执行顺序、TESTS管完成门槛、S0固定契约管跨模块接口、DESIGN管内部技术方案。批准的计量基线不被增补计划暗改。实际代码和测试只能证明对应版本能力，不能自行变更目标。遇冲突先记录并核对权威来源，不简单以文件修改时间或最长文档为准。

入口和CURRENT只导航、不复制详细方案；历史prompt、旧审批HTML、归档与已关闭batch为P3，不作为当前增补开发指令。已有冻结摘要/测试报告不为本轮整理重新生成，新的整理检查单独保存。

## 协调会话与任务会话

协调会话负责粗粒度任务划分、公共边界、文档索引、阅读范围和人机工作方式。各任务会话分别与用户开展调研、讨论、设计和实现，逐步收敛本任务的第一版目标。

任务是持续维护的工作领域，session 是承担它的会话。同一任务可以由后续 session 接手；不按聊天 ID 命名代码，不因一次任务划分自动同时启动所有会话。

## 一个任务的文档入口

已建立 [任务入口索引](../../../../../docs/tasks/README.md) 及五个任务的精简入口。已有按资料类型的目录继续保存公共或原始内容。任务结构如下，实际 batch 在设计中确定后才创建：

```text
docs/tasks/<task>/
  ENTRY.md              当前状态、目标来源、阅读清单、依赖和可修改范围
  DESIGN.md             人与对应 session 共同维护的当前设计
  CODEMAP.md            相关源码入口、关键符号、测试与配置位置
  batches/
    B001/
      CONTEXT.md        本 batch 所依据的设计与接口版本、阅读范围
      PLAN.md           行为变化、修改范围、测试与回退安排
      RESULT.md         实际改动、验证证据、偏差和后续交接
```

公共数据和接口定义继续放 docs/contracts，研究依据放 docs/research，原始现场材料放 evidence、核对结论放 docs/huawei。任务入口用链接选择需要的部分，不复制全套公共文档。

memory/CURRENT 只路由到当前任务或协作入口；memory/SESSIONS 记录实际会话分工。任务 ENTRY 维护本任务状态，避免同一状态在多处详细重复。已有 docs/stages 模板暂保留，不与任务 batch 同时建立重复计划。

## 阅读范围和优先级

| 层级 | 默认内容 | 作用 |
| --- | --- | --- |
| P0 项目与任务入口 | AGENTS、精简 CURRENT、本任务 ENTRY | 恢复约束、当前工作状态与下一步 |
| P1 当前工作必需 | 本任务当前设计、当前 batch、直接依赖契约、相关源码和测试 | 执行当前任务所需的完整上下文 |
| P2 解释和追溯 | 被设计引用的研究结论、固定源码片段、关联现场证据和决策 | 需要理解依据或定位疑问时再读 |
| P3 历史 | 旧设计、已完成 batch、历史日志与归档 | 当前结论需要追溯时按链接查阅 |

P1 随工作状态变化：调研读目标输入与相关来源；设计读调研结论、约束与依赖接口；编码读已共同确定的设计、当前 batch、代码地图及相关代码；评审读变更、依据与验证证据。没有实现的任务不要求虚构代码入口。

阅读清单必须列具体文件、章节或符号及其用途，不写“阅读整个 docs/upstream”。相关实现和测试仍要读足，不能只凭摘要编码；遇到依赖或失败沿调用链扩展阅读，并将新增的长期必要入口补回 CODEMAP。

跨任务默认读公共契约和必要示例。需要定位接口问题或修改共同实现时，再追到相关任务源码，不要求为每个 batch 重读全部其他任务设计。

## 文档演进与依赖更新

- 当前设计原地维护版本号、日期和状态，重大旧版需要追溯时归档；当前入口只链接一个有效设计。
- 研究可以保留多种候选，设计明确实际采用哪些结论；实现只依据当前共同确定的部分，不自行把研究建议升级为开发目标。
- 每个 batch 记录所依赖的设计、接口与源码身份。已有 Git 时可用 commit，尚无 Git 时可用明确文档版本与文件摘要。
- batch 开始时只核对自己的直接依赖是否变化。变化影响当前工作时重新判断方案；无关文档迭代不触发全项目重读。
- 共享接口指定维护任务并登记消费者。变更说明列出影响和兼容方式，协调会话处理跨任务冲突；不把同一契约复制到各任务后分别修改。
- 批次结束更新本任务入口、代码地图和结果；历史日志不持续追加到 AGENTS 或全局 CURRENT。

## 人与机器共同完成设计

进入代码开发前，人与该任务 session 共同确定适用部分：

- 开发目标、使用场景、可观察行为和本次不做的内容。
- 输入输出、数据与接口约定，以及与其他任务的依赖。
- 代码要求，包括 clean code、模块职责、命名、错误处理、可配置项、依赖和复杂度边界。
- 开发 batch 及相互依赖，每批要形成什么可检查的变化。
- 测试方案、必要样本、已知限制，以及失败时如何判断。
- 回退范围和方法，以及需要重新与人讨论的变更类型。

这里约定设计应回答的问题，不提前替各任务填写具体实现或数值验收门槛。开发前提可以按已收敛的部分建立，不必等待与该部分无关的全项目设计。

## 设计收敛后的 Batch 开发方式

采用用户已同意的“约定范围内自主推进，关键变化回到人机讨论”方式；实际启动任务时明确授权覆盖整个任务还是部分 batch。

1. 读取当前 batch 的入口、已确定设计、直接依赖版本、相关代码和测试。
2. 确认本批修改范围和可追溯起点，核对共享文件的最新状态，保留其他 session 的工作。
3. 实现本批行为；在约定范围内选择常规实现细节并修复问题。
4. 运行本批必要测试，检查设计符合性和代码质量；失败则定位、修复并重跑受影响检查。
5. 记录实际改动、验证证据、未解决问题和回退方法，更新本任务入口与代码地图。
6. 若下一批已在授权范围内、依赖满足且当前没有阻断，则继续下一批，无需把每个 batch 的完成都变成新的批准请求。

目标、业务语义、共享接口、已约定测试要求或回退策略发生实质变化时，先说明具体影响并回到相应任务的人机讨论。普通实现选择和测试修复在既定范围内自行处理。打包仍执行用户已明确的同意要求。

回退必须针对本批自己的修改；共享工作区中不能用全局 reset 覆盖别的 session。Git、分支或 worktree 的具体协作方式另行确定，任务规划本身不创建仓库或工作树。
