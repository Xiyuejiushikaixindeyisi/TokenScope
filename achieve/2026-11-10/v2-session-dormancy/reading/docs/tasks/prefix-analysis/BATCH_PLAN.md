## 1. 实施边界与顺序

公共契约 → 来源/编码桥接 → 受保护修改/统一评估内核 → 候选索引及L2 → L1/L3 → L4/L5 → 小范围/全范围筛选 → 后台任务/存储/顺序调度 → HTTP及两线联调 → 资源校准/回归/交接。

工程上先做L2，是因为它有可精确验证的同集合排列条件，适合验证“发现→具体变换→统一回放”通路；L1/L3随后共享动态槽位差异与删除处理。L4/L5以完整证据输出为主。此顺序不代表运行时原因优先级；正式任务仍检查全部适用L1–L5，不首命中停止。

- 只分析目标appid、同源/服务/编码身份、选定窗口；不增加全历史、跨appid或跨run预热。
- 首期手动指定原因和开关：low_hit为两方向依次执行；只有request_length/qps则仅Token。32k/70%不是自动触发阈值，不承诺诊断Loop/QPS过程原因。
- L1/L3可直接生成明确动态字段删除候选并离线验证，不先要求业务无损批准；不执行线上修改。
- 小范围完整实验ΔR>1pp才自动全范围；全范围ΔR>1pp才显示优化卡片；严格使用未舍入的绝对百分点差。Token报告、L4/L5完整JSON差异证据独立。
- 全范围指已冻结目标范围全部有效请求，含未修改请求；零/负结果后台保留，失败不能丢行发布收益。
- 不开发前端、监控采集、模型配置优化、自进化Agent、原生新协议适配或打包部署；不启动其他会话或委派Agent。

源码范围沿用[CODEMAP](../../../../../../../docs/tasks/prefix-analysis/CODEMAP.md)：主会话新增analysis_common、prefix_analysis及diagnostics装配；Token包token_content由子会话维护。现有编码和缓存算法只复用，不复制或变更语义。共享app.py/cli.py/配置的实际编辑须届时重读SESSIONS并登记窗口，避开正在进行的监控联合审查；本计划不预占共享源码。

## 3. 每批内容与验收细则

### LH000：公共契约及测试基线

产出：正式公共类型/元数据编码规范、插件与处理器调用边界、状态/错误及HTTP字段协议、独立构造fixture清单；在用户授权实施后才建立必要类型骨架与契约测试。固定契约另存版本化文件，draft-2保留来源身份。

必须明确：

- RequestKey、SourceIdentity/Selection、AnalysisScope、RequestView；raw_body_complete与capture_truncation分离，可空字段语义和十进制字符串wire。
- location/unit/observation身份、父子重叠、规则/策略版本；参与三态与精确Token spans独立，未检查/未知/未检出不同。
- TargetLocation、PreparedMutation、Plan/manifest及静态registry；Token内嵌JSON由本线编译为受保护外层替换，公共层应用。
- 两阶段结果、confidence_basis、display_eligible、direction/stage状态；中止/预算耗尽不伪装成功。完整两请求读取协议必须明确范围绑定及原文字节身份。
- reason_codes与开关一致性；低命中与Token顺序，公共源失败和方向局部失败分开；小范围不足不得伪造高置信度。

验收：合法/非法载荷及状态转换表可逐项验证，稳定身份有固定编码输入/预期摘要样例，门槛有0.99/1.00/1.01pp预期，重复hash_id不合并。接口交接H0给出实际版本/摘要与变更说明；对方尚未接收就登记pending，不代签。无须重开已批产品设计；字段层歧义在实现前解决。

### LH001：只读输入与统一编码桥接

拟范围：analysis_common/source.py、encoding.py及必要类型实现。基于user_v2/base真实发布身份解析服务/模型；只读联接有效编码请求，按time_ns/source_record_index稳定迭代。原文及IDs按需读取，不把预览用于规则。

验收：

1. 一个run内两个appid互不污染；相同时间、重复hash_id、窗口边界、空范围正确。MA作为人工背景不混入用户请求计算。
2. 完整正文大于64KiB仍可读；原文/TokenSlice/资产摘要失败给具体原因，不静默丢行；source与修改结果身份不混。
3. 用项目固定三模型资产、原profile/effective_options复现P/IDs及已有编码证据；源Requests/切片摘要前后不变。资产缺失记录blocked，不能以假编码器关闭此项。
4. 映射未知可继续内容事实；一次对照不变不判永久ignored；messages边界不被悄悄扩成原生instructions/input。

交H1：真实resolve_scope/iter_requests/read_ids及编码桥接可调用版本、输入fixture、能力矩阵；支持Token TA001–TA003接入，仍不声称任务/API完成。

### LH002：修改及单次评估内核

拟范围：analysis_common/modifications.py、evaluation.py、处理器registry基础。内核一次计算一个明确scope+Plan；pilot/full筛选由LH006组合使用，不写第二套评估算法。可返回可序列化结果和manifest，生产封存/恢复在LH007落地。

验收：

1. 准确字段/字符串范围、工具排列、受保护外层替换和已批普通消息删除等公共原语；原值/缺失guard、Unicode坐标、原始数组索引正确。同位置相同操作去重，父子覆盖/冲突拒绝；同外层多个内层操作由对应处理器一次编译。
2. 未目标结构不变，未修改raw保留；序列化影响单列；validate_request不绕过。任一目标失败整个方案无after，不能伪装不适用。
3. 对真实编码的合成窗口，用监控make_strategy直接处理相同IDs的结果作适配等价对照，并辅以人工IDs小样本的明确H/C预期；原run复核、子窗口空基线、MTP/块边界/cache off均覆盖，不把同一个封装重复调用当独立验证。
4. before/after的P=H+C、汇总R=ΣH/ΣP正确；P=0不可用，原O无after；改动子集和全范围分列；实际组合重放不求和。源库不得调用有写入副作用的replay。

交H2：真实Plan→评估内核、PreparedMutation协议及manifest版本。Token TA004可据此验证处理器及实际三模型编码；临时合成处理器仅验证公共边界，不能代替真实Token插件验收。

### LH003：前序索引及L2

拟范围：prefix_analysis/structure.py、candidates.py、comparison.py及L2。SQLite引用索引和有界IDs缓存；按服务/有效选项/结构/工具定义召回，先查询再入历史。实际字段逐值核验，不只比较hash。

验收：当前及未来请求不可作为对照；候选预算截断标partial、不称全局最优；稳定排序和同分对照可复现。LCP和H分别输出，不将结构近似称同session。L2同完整定义集合但排列不同才成立，重复工具身份降级，数量/定义改变交L3；messages/tool_calls不被重排。对真实编码窗口完成L2单次副本评估，保留零/负结果，不要求所有fixture都能提升。

### LH004：L1/L3动态内容及修改建议

拟范围：L1/L3探测器、动态槽位比较、准确删除候选及共享去重。识别已知cch行，并按实际可比请求变化发现普通时间、路径、标识；语法只供检索，不从字段名直接断言异常。

验收：

- 已知cch、普通业务时间、工具description动态路径均有正例和稳定/同名正文反例；单请求元数据存在不伪装变化频率。
- 普通动态字段可实验，无额外业务无损审批；准确展示被删内容，action_class区分，但不改变评估门槛。非法结构不因潜在收益绕过校验。
- L3工具集合增删及Schema差异有准确路径，合法版本变化不自动称错误；不选择最常见版本覆盖其他定义，不顺带删除实际调用参数。
- 两个动态因素单改零收益、组合改善的fixture保留共同候选依据；同位置L1/L3共享证据/计划，不能双算请求或收益。
- 按具体删除副本实际编码建立输入影响证据，不用字段字节或掩码LCP充当Token收益。

### LH005：L4/L5及完整请求证据

拟范围：L4/L5探测器、完整请求对照对象及引用生成。无可靠关联时L4只报告可比请求内容差异；有真实关联证据的合成测试验证识别能力，不因此增加采集或声称现场具备session。

验收：

- 正常append-only、模板末尾生成标记、已知合法压缩不误报；历史变化位置明确，关联来源可空且准确降级。
- L5严格JSON解析、重复key/非有限值/数值保真、true与1及数组次序、代码/Markdown/签名场景；外层JSON不同但实际IDs相同不报缓存影响。
- 每条对比含两份完整原请求引用、键、摘要、差异路径，正文大于64KiB仍可完整读取。格式化视图不覆盖原文，不抹掉L5内嵌字符串差异。
- 无收益可独立输出差异证据，不写0冒充未评估；测试用[完整样例](../../../../../../../docs/tasks/prefix-analysis/FULL_REQUEST_COMPARISON_EXAMPLES.md)及长正文反例。此批不要求实现可选的L4历史修复或L5规范化收益链路，不以它们阻塞本期必需交付。

### LH006：两阶段实验与筛选

拟范围：prefix_analysis/service.py及公共评估scope选择/阶段结果封装；只调用LH002同一内核。冻结全范围F，为具体方案确定连续S，记录选择依据与版本。小范围通过后以同一transformation_digest展开F中准确适用目标。

验收：

1. S为F内连续记录，包含其间未修改请求；两侧同空账本。无法在预算内包含所需对照/发现时给原因，不悄悄拼接远距离请求或反复择优。小范围不足显式标记，用户指定直接全范围的例外不得写成pilot通过。
2. 原始整数指标的精确比值比较：未舍入ΔR严格>1pp；接近边界的浮点误差不得改变门槛。至少覆盖0.99/1.00/1.01pp及显示四舍五入相同而真实判定不同的样本。
3. pilot未通过/失败不自动full；pilot通过但full≤1pp不展示卡片；变换参数变化须重新pilot；P=0、窗口为空、预算不足均有明确结果。
4. 全范围必须计算F中全部有效请求含未改后继；原run和子窗口基线模式明确。零负后台可查，前端仅接收达标卡片；L4/L5差异证据与Token报告不套门槛。
5. 组合候选有边界和预算，独立经历pilot/full，不把组合通过赋予成员高置信度；失败无after。R升但C升的样本展示全部指标，不称成本降低。

这一批完成纯服务级实验流程，不宣称后台崩溃恢复已完成。资源限制先用明确测试配置；生产默认值在LH009校准并回归，不在此凭空定值。

### LH007：公共存储与顺序任务

拟范围：analysis_common/storage.py、service.py、processor.py，必要共享Dispatcher注册待登记后修改。派生库与源库隔离，结果/证据封存；静态插件/handler registry消费纯fragment；阶段内部调用不重复持有worker.lock或等待自己排入的子任务造成死锁。

验收：

- 同幂等键同意图返回原任务，异意图拒绝；retry新attempt，历史不覆盖；rename/事务发布之间崩溃、磁盘/DB故障不会发布半成品。GET不修复、不补算。
- 原因/开关矩阵与顺序：低命中所有已调度pilot/full结束后Token；仅长度/QPS直接Token；没有发现或方向局部失败可继续Token，共享源破坏及中断不继续。没有告警触发或监控outbox自动消费。
- 不适用、未查、partial、failed、interrupted明确；预算耗尽未评估方案记not_run及原因后结束该阶段，不以“永远pending”阻塞Token；预算导致未查不能把总任务写全量ready。
- Token插件尚未提供时返回明确能力缺失/未执行状态，不能空报告冒充成功；合成插件仅用于控制流测试，真实两线通路留给LH008。
- 同步复用原进程CPU预算及worker锁，无新并行编码池；停止按规定边界，未完成评估不发布收益。分方向已完成证据可保留。

交H3a：真实公共后台服务及持久化、版本/状态协议，供Token准备TA005服务级接入。
