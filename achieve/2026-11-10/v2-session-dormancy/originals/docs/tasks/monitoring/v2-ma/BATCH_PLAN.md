# MA监控 v1.0：Agent分批开发与闭环

2026-10-30；配套[最终设计](DESIGN.md)。**M000–M005已按本计划逐批闭环；本机后端最终235项测试通过，见[M005 RESULT](batches/M005/RESULT.md)。下文为执行规则及原计划。** 用户启动实施后按本方案依次推进；暂不部署/打包。

## 1. 开发Agent的执行规则

1. 每批开始前读最新CURRENT、SESSIONS、本设计和当前batch PLAN/ISSUES/TESTS/RESULT，核实实际ID、用户授权、前批closed和公共文件维护边界。只读当前批所需依赖；锁定源码/契约/资产/环境身份，不能沿用历史SHA作本次证据。
2. 在本批PLAN补入确切文件/符号、数据流、事务、错误处理、测试步骤、影响/回退。设计中的未来路径是拟建对象；创建前核对最新代码，不能把不存在的测试命令记为成功。
3. 实现→针对性测试→审查→修复→相关复测；普通实现缺陷在授权内自主处理。每个batch通过其必需门槛后，先写RESULT和增量记忆再开始下一批，不因“主功能可用”跳过失败项。
4. 状态为planned→in_progress→verifying→closed；受依赖阻断记blocked，修复后回verifying。缺证据、必需测试skip/未执行、未解决的正确性/兼容/数据安全问题都不能closed；不能把它们降级“后续优化”换通过。
5. 重大需求、指标含义、契约不兼容、验收门槛或公共所有权变化先登记偏差并与用户确认；不重复申请已授权的常规batch内操作。设计定稿、开发启动、生产部署/打包分别授权。

## 3. 共享代码职责及接入基线

| 范围 | 唯一实施方与消费方 | 约束 |

| CSV时间解析、别名初始化、DeepSeek默认/迁移 | 用户监控线；MA消费 | MA不复制修复。M000记录接入revision/接口；原UTC/ISO路径仍回归 |
| 统一ModelEncoder/批编码/Token分片 | 公共现有实现；本线默认仅消费 | 需要改动时另登记具体符号与唯一方，不因MA文档宣称接管 |
| FullBlockStrategy/PrefixLedger | 公共现有实现；MA通过范围适配复用 | 保持V1调用与键，不改其appid事实、不复制算法；改签名须双方兼容样例 |
| V1 distribution与用户开放排行箱 | 用户线负责自身新增排行；MA读取旧distribution | 旧0–200K/尾桶、最近秩保持不变 |
| monitoring/ma/、MA投影/控制库/接口适配/MA验证 | MA线 | 不写旧control3/view1结果、旧seal或用户排行 |
| api/app.py、cli.py、service装配 | M004由MA线登记新增MA接入的具体diff；用户线同时涉及该文件时按顺序接入 | 开批前重读/核对变更；不整份覆盖，不给整文件永久独占权 |
| worker.lock与dispatcher | MA线维护可注册共享调度，用户线实现索引/回填process_next适配器 | V1、MA和已接入用户重任务同额度，覆盖HTTP/CLI；非嵌套轮转。M000/U000固定注册接口，用户真实未就绪则联合pending |
| 监听、Compose及对外访问 | 用户线设计职责，实际交付由审查打包负责 | 本轮及本计划不执行部署/打包，不修改现场运行配置 |

每个batch记录`accepted_common_baseline`：源码commit＋相关文件SHA、Python/依赖锁、资产锁、模型设置revision、MA协议SHA、旧S0 SHA，以及用户线已实现/未实现的接入能力。双方不需等对方整线完成；某公共能力缺失可使用已支持的显式配置完成不相关工作，但相关验收不能写通过。文档登记不等于对方签收，不自动发送消息/唤醒会话。

## 5. 检查与证据要求

在项目固定Python3.11环境使用pytest、ruff、format --check、mypy；确切解释器/命令和输出写本批TESTS。M001–M004运行当前组件及受影响回归，避免无变化地反复全仓测试；M005必须完整运行项目Python测试及约定静态检查，验证MA真实HTTP/CLI和既有S0。新增类型模块纳入strict检查，不通过随意禁用规则消除错误。

有意义的夹具覆盖跨UUID/跨租户、pre暖场、相同hash独立行、输入计量不一致、真实字段缺失、非法JSON、时序冲突、零分母和超200K。期望值由独立小例/参考推导给出；不调用待测实现生成自己的expected。

原始日志/合成运行产物放`artifacts/validation/monitoring/v2-ma/<batch>/<attempt>/`（实施时创建），源数据不入Git；小型证据清单、摘要和结论留docs。记录命令实际执行而非复制“预期通过”；历史V1或兄弟项目测试不可计为MA本轮测试。

## 6. 最终闭环与回退

M005在固定候选源码运行完整流程，输出逐条设计对照、统一E2E、健壮性、兼容与资源报告。失败先修复并运行相关复测；改动影响多个阶段时重跑对应batch必要门槛，最终报告必须绑定同一候选身份，不能拼接不同版本的通过结果。

开发回退为停止新dispatcher、恢复本次受影响源码/可选MA接入、保留MA数据证据；旧V1库/seal不被修改。回退前保存运行与版本身份，不删shared state，不全局reset或清理其他会话工作。当前不构建Docker，不创建交付包，不修改V1正在运行的配置。
