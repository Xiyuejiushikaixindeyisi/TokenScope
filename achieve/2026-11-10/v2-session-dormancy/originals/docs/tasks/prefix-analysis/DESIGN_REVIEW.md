# 低命中率后端详细设计评审要点

> 本评审的A/B/C/D已由用户确认，并有重要修正；以[prefix-design-0.2](DESIGN_REVISION_20261031.md)为当前入口，不再请求重复确认。本文保留上一轮取舍背景。

2026-10-31，评审整理稿，不是冻结接口或实现结果。依据[DESIGN](DESIGN.md)、[公共草案](../analysis/BACKEND_COMMON_CONTRACT_DRAFT.md)，并已读取Token线[TA-I0.1需求](../length-analysis/INTERFACE_REQUIREMENTS.md)与[TA-D0.1设计](../length-analysis/DESIGN.md)。本稿的公共扩展为主会话建议，未宣称双方签收。产品v0.4保持，不编码。

## 1. 整体执行

固定源运行、appid、服务/编码身份与窗口 → 读取有效请求 → 查询前序结构候选 → 比较源字段与实际输入IDs → 执行全部适用L1–L5 → 保存发现/证据/候选修改 → 显式离线评估 → 读取不可变结果。

候选检索使用工具集合、消息结构、已知动态槽位和稳定文本索引；只查更早请求，先查后入索引。它用于找可解释对照，不替代理想缓存算法、不推断session，也不保证全局最佳对照。各规则收集独立观察，没有L1到L5的归因优先级。候选预算影响覆盖时明确partial；计量回放仍必须覆盖声明的完整窗口。

## 2. L1–L5实现与证据

| 规则与机制依据 | 判定和证据 | 建议/修改与限制 |
| --- | --- | --- |
| L1 动态元数据：前置动态值使后续相同输入失去共同前缀；已批研究含CC billing/cch案例 | 已登记位置/头部语法识别；比较前序相同槽位、稳定后文；保存源Pointer/字符串范围、不同值摘要、IDs首差及参与证据。单请求只能证明元数据存在 | 已知误注入cch按准确范围删除，沿用业务信息无损结论；其他动态业务字段不自动删。当前只覆盖实际支持的messages文本，不新增原生instructions协议 |
| L2 工具排列：工具被序列化为模型输入，排列波动破坏前缀 | 唯一工具身份、完整定义多重集合相同、排列不同；逐值确认，不仅比较hash；保存前后排列和输入差异 | 固定身份排序，保留定义、数量和权限。名称歧义不自动排；不排序messages/tool_calls。定义不同交L3 |
| L3 工具定义/集合漂移：定义文字、Schema和工具集合变化会改变输入 | 同身份字段级diff、集合增删、定义版本；分别记录内容变化与模型输入变化 | 有依据的动态元数据按L1清理；有明确标准定义才替换。合法权限/版本变化不判错误，不从多数请求猜标准 |
| L4 历史前缀改写：正确增量追加保留既有历史，旧内容改写可能破坏共享前缀 | 有可靠关联才比较同链旧messages；排除正常追加、合法压缩和模板生成标记。缺关联仅报告结构差异，原因未证实 | 当前不自动重建历史。只有真实关联及明确追加规则时产生具体修改；不从appid/时间相邻推断链路 |
| L5 序列化不确定：结构相同但实际输入表示不同可破坏前缀 | 限已声明JSON字符串；严格解析，类型/值及数组顺序一致，只对象key顺序/空白不同；再检查实际IDs | 只规范化目标字符串，保留数值语义。无法保真则不生成方案；不改代码、Markdown、签名字节。外层JSON不同而IDs相同不算低命中原因 |

机制及研究来源沿用[已批探测规则](../analysis/LOW_HIT_DETECTORS.md)，本稿没有新增未经调研的探测器。某字段有差异不代表全部未命中都由它造成；LCP为请求对共同前缀长度，H为统一策略计算的命中量，两者分列。

输入参与分三层：源字段差异、实际IDs差异、字段到输入的参与证据。精确字段Token归属允许为空。建议优先使用真实候选修改的对照编码；必要时有预算的单字段合法探针只作参与核验，不进入收益。一次对照无变化只证明本次操作无可观察影响，不能证明字段永远ignored。DESIGN第5节“无缓存影响”按此限定理解。

现有monitoring.replay会写源库，因此不对封存源调用；user-v2 evaluations是TTFT公式，不是本功能的输入回放。现有explain提供渲染offset，尚不提供精确原字段Token归属。新增诊断命名空间和结果库为提案，不声称已经存在。

## 4. 离线评估

1. 固定scope、请求顺序、计划版本、原值guards和修改参数。只回放目标appid本窗口，不拼接其他run。
2. 核对源seal、资产、encoder、Template、profile及算法身份；用原实现复核基线。
3. 原run范围模式核对原IDs/P/H/C；选子窗口模式前后都从该窗口空账本开始，源全run H/C仅作背景。
4. 修改结构副本，校验原值、协议和非目标不变量；未修改请求原样保留。内嵌JSON按专用路径严格解析/回写，不能正则改原文。
5. 编码修改后请求；任一选中目标失败则整个方案受阻，不漏掉失败行发布收益。
6. 两个独立账本按相同顺序计算整个窗口。组合方案先查冲突，再实际执行，收益不能相加。
7. 保存逐请求与汇总N/J/P/H/C/R、变更清单、覆盖、基线来源及限制。R=ΣH/ΣP；P为0则不可用。Δ统一为after−before，另列节约C=before−after；R变化使用百分点。

全窗口指标为主要效果；修改子集另列，说明未修改的后继请求也可能受前缀稳定化影响。必须同时展示P、H、C、R，允许P下降而C增加。O只保留源值，不估计修改后输出、费用、TTFT或质量。评估证明输入计量变化，不证明Agent任务结果等价。

## 5. 与Token会话公共边界

主会话01a18be2-7112-7aa2-919b-5137d1f1b1ad维护公共类型/来源/存储/编码桥接/评估/API集成及L1–L5；Token会话01a18fcd-0464-7cf1-b435-4f394bd33e66维护T1–T4、策略及本线纯变换处理器。双方不依赖对方探测器内部类。

公共输入为RequestView+AnalysisScope；公共输出为规则状态/覆盖、Observation、FindingCandidate、ModificationCandidate；显式计划经evaluate_plan统一评估。RequestKey使用base_run_id+source_record_index，不用hash_id冒充唯一键。

读取TA-I0.1后建议纳入下一版公共草案的六项细化：

1. 分开raw_body_complete与source_truncation：已完整读取存储原文，不代表采集前没有截断；未知保留unknown。
2. 模板参与included/ignored/unknown及依据，与可空精确Token区间分开；单次无影响不直接标永久ignored。
3. ContentUnit按源身份、路径、内嵌路径、表示/解析版本确定身份；支持多位置和父子重叠关系。T2/T4共享内容事实，不按rule_id复制总量。
4. Plan增加embedded_pointer、解析/序列化版本及外层guard；明确普通消息授权删除和原始数组索引解析，多个操作原子应用；Token纯处理器以版本化注册表接入，不能写源库。
5. EvaluationResult明确全窗口与修改子集；blocked/failed不含after，not_run不是零收益。
6. 共享预算/停止上下文：请求边界检查停止；分析保留已完成覆盖，评估未完成scope不发布after。首期不因此增加用户取消API；异常中止/重试由公共生命周期处理。

以上是已读取需求后的建议接受范围，尚未冻结Schema或登记双方联调通过。依赖顺序：公共输入/证据Schema → 两线纯规则可分别实现；公共Plan/处理器协议 → 两线修改接入；公共评估/存储/调度 → 联合验收。精确映射缺失不阻断Token内容事实；真实session缺失限制L4，不阻断L1/L2等。

## 6. 待用户确认的技术取舍

| 点 | 推荐方案 | 影响 |
| --- | --- | --- |
| A 执行与资源 | 显式异步诊断/评估，独立/diagnostics及派生结果库，接现有Dispatcher/锁；不额外起并行编码池 | 隔离源数据，复用资源治理；可能排队，初版不承诺抢占或实时响应 |
| B 证据深度 | 结构+IDs比较为基础，必要时按预算做真实修改对照/单字段参与核验；不建设通用精确字段映射引擎 | 可给可复核原因和实际评估，部分字段归属仍unknown |
| C 规模与覆盖 | 索引召回、有限候选深查，逐规则公开覆盖；评估必须完成整个声明窗口；预算值由后续规模测试校准 | 控制比较成本；不承诺穷举全部原因，不凭空设生产默认值 |
| D 公共契约细化 | 接受第5节六项，形成下一版统一Schema/处理器协议，再实施 | 两线复用一套证据/计划/评估，不形成第二套计量或存储 |

L4缺关联降级、appid范围、cch清理、工具稳定排序、离线组合重算、Loop保留数据需求均是已批范围或数据事实，不重新请求产品审批。基线模式随用户选择窗口自动确定，不再让用户选择含混口径。本轮只做技术评审整理，未启动开发批次。
