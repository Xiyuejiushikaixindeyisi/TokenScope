## 1. 范围与输入

用户选择源监控运行、appid、模型服务/编码身份及分析窗口。默认使用该appid原运行窗口；有效请求键、排序、内容/配置摘要形成固定范围。对缺失/跳过数据报告原因和数量，不把未知归属的文件级跳过数摊到appid。

区分三个集合：

| 集合 | 含义 |
| --- | --- |
| 分析范围 | 目标appid所选窗口的有效请求 |
| 已检查范围 | 本次实际检查/有足够输入的请求；抽样或预算限制必须显式显示 |
| 修改范围 | 某个方案实际应用的请求，是分析范围子集 |

评估默认覆盖分析范围中全部有效请求，包括未改记录，以计入后续缓存影响；不回放其他appid。只评估子窗口也可行，但必须将该子窗口作为前后共同基线，不与其他历史条件的原H/C混比。

## 2. 内部校验与可用性

后台读取原文、IDs、原指标及资产/模板/缓存规则身份。context_check、format_visibility不注册为业务探测器：

- 原文可用但IDs/资产不可用：可做内容/结构事实，低命中输入影响或量化评估显示受阻。
- 只有字段大小：可给内容排行，字段Token贡献留空。
- 没有tools/tool消息：对应项不适用，不阻断其他内容。
- 缓存关闭：说明原H口径，仍可评估P变化；不把配置关闭归因于用户prompt。
- 没有可靠关联：不把结构相似请求当同session；L4过程结论受限，T4仍可做单快照内容清单。

块/MTP及边界解释仅在技术详情引用监控结果。LCP不等于H，H=0不表示完全无共同前缀；不由H反推实际缓存来源或分歧位置。

## 3. 两条分析路径

~~~mermaid
flowchart TD
    A[选择目标appid 服务 窗口] --> B[内部校验与统一输入引用]
    B --> L[低命中率分析 L1-L5]
    B --> T[Token内容分析 T1-T4]
    L --> C[保存独立发现及共享证据]
    T --> C
    C --> D[明确修改字段 保留规则与作用范围]
    D --> E[显式离线评估]
    E --> F[同窗口基线与修改副本重放]
    F --> G[保存前后指标与差异]
    C --> H[业务报告 两个页签]
    G --> H
~~~

**低命中路径：** 建立合格前序对照 → 比较原字段/工具/消息 → 核验模板后输入差异 → 按L1–L5归类 → 展示可修改问题及未解释变化。对照来自同范围前序请求；形状/掩码仅用于候选召回，不证明语义相同。未找到对照不等于语义唯一或不可优化。

**Token路径：** 枚举工具定义/返回/重复载荷/历史结果 → 计算同单位内容度量并去掉重叠计数 → 核验模板参与 → 按T1–T4给事实和规则判断 → 形成明确保留/替换建议。正常历史增量携带不作为浪费。

规则没有固定先后优先级。适用项继续检查，每项记录完成/未检出/不适用/输入不足/未完成/失败；预算停止不得当作未检出。证据充足的事实可发布，不等待所有评估完成。

## 4. 归组与输出

同一位置和同一修改动作的多种观察归一张主卡片，用关联规则标签说明。不同位置可分别展示，但：

- 当前请求数按键取集合并集，对照请求不额外算“受影响请求”。
- 每个分组保留逐条观察、不同代表样例和冲突证据。
- 规则事实、异常结论、动作类别和收益状态分别记录。
- 一个请求可有多个问题；不能强行把全部C分摊给这些原因。
- 公开依据证明机制存在；当前请求证据证明现象存在；同窗口评估证明该方案的静态计量效果，三者不互代。

## 5. 修改方案

首期只做明确原请求字段上的操作，不调用模型摘要，不重新执行业务agent/工具。

| 操作类别 | 例子 | 可评估前提 |
| --- | --- | --- |
| 已知业务信息无损清理 | 去掉误注入输入的CC billing/cch元数据行 | 来源/位置已识别，匹配规则限定该元数据，非任意正文 |
| 稳定化修复 | 同集合工具固定排列；明确JSON载荷确定性表示 | 保留工具定义/数量/权限，或验证结构值不变；身份冲突不强行修复 |
| 内容调整/裁剪 | 精简description、保留指定列/行、按策略保留历史结果 | 具体路径、文本/参数、保留规则；标明信息变化，不默认业务无损 |
| 已有协议下引用替换 | 文档正文改为工具已支持的对象引用 | 引用真实可解析、工具已有该语义；不能凭空假定 |
| 仅建议 | 工具搜索/延迟加载/执行侧聚合，缺具体副本 | 不给量化收益，也不为评估而实现新架构 |

修改清单固定请求键、字段路径、原值条件、操作参数、前后摘要。不能直接删IDs，不对整段渲染文本通配删除。目标修改失败则阻断该方案，不偷偷丢弃失败记录。合法不适用记录保持原样并计数。

## 6. 两种基线，均只涉及目标appid

**沿用原运行窗口。** 同appid、服务、窗口、排序及起点复现基线；核对IDs/P及同口径H/C一致再发布与原监控可比的结果。

**用户选定子窗口。** 首期用该窗口独立空起点，分别重算修改前与修改后。源IDs/P在可比编码条件下需一致；H/C无需与原更大窗口一致。页面写“本窗口重算基线”，源监控H/C仅作独立背景，不能混入收益计算。不新增缓存快照恢复功能。

两种模式均保存基线来源、实际请求集合、空起点、排序、模型/资产/规则身份。基线不一致、资产不可用、输入不完整导致无法完成所选范围时，评估受阻；不发布不完整结果冒充全窗口收益。用户显式选择可完整评估的更小范围时另建基线。

## 7. 回放和指标

每个单项从同一原输入建立独立副本/缓存账本，复用监控统一编码与理想命中实现。组合方案先核对路径、覆盖与操作顺序，冲突先解决，再实际重放；单项和不是组合收益或一般上界。

| 指标 | 定义/展示 |
| --- | --- |
| N、J、P、H、C | 相同请求集合的总量；H+C=P，指标来源与配置固定 |
| R | ΣH/ΣP，零分母为不可用 |
| ΔP、ΔC | 前−后；正为减少，负为增加 |
| ΔH | 后−前；显示带符号值 |
| ΔR | 100×(后R−前R)，单位“百分点” |
| 作用范围 | 修改请求数及评估请求数分开；默认展示整个appid分析窗口 |
| 辅助子集 | 可展示修改记录的变化，但不与全窗口结果相加 |

O仅保留源计数，不生成修改后O；不推断未来调用次数、真实费用、TTFT或任务成功率。命中率提高不等于Token负担降低；P降低也可能破坏旧前缀、使C增加。零收益和负收益均为有效结果，不能隐藏。

## 8. 发布与业务操作

报告显示所选范围、已检查数量、原/重算指标来源和两个页签。每张卡片有“看证据”“看修改”“离线评估/查看结果”；动作不可用时写明缺少的具体字段或规则。

初次分析只产生发现和可明确生成的候选；是否评估由显式动作触发。评估预算与覆盖公开，不在页面GET时计算。首屏折叠不影响探测完成状态和评估资格。

低命中页重点看稳定前缀、ΔC及ΔR；Token内容页重点看内容位置、保留规则、ΔP，同时必须显示ΔC。使用同范围已完成结果排序；未评估项按内容事实/涉及量展示，不伪造预计收益。逻辑字段见[字段草案](RESULT_FIELDS_DRAFT.md)。
