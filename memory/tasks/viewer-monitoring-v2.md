## 职责与必须保留的边界

- 用户监控：GB appid×common_name，单运行显式服务绑定、租户隔离、空缓存起步。展示后端提供的用量/理想复用、搜索排行和P90长度参考命中率；服务级理想值不能当成某UUID真实命中率。
- 用户排行：四项为请求数、理想命中率、理想重算Token总量、典型重算长度。典型长度是C=P−H的众数区间内均值，并列取lower最小箱作为代表且保留并列提示；不是原DEMO的模板后输入众数起点。固定user_run/common_name，appid区分大小写字面子串；全候选先过滤排序后分页，绑定index_revision，缺值最后。开放等宽C箱与V1/MA的200K尾桶不同。
- TTFT：标签为“P90长度请求所需参考前缀命中率”。消费后端固定chunk情景及T/W/O/K/τ、证据来源/适用条件、状态和限制；人工假设与实测分开，缺参数/无预算/越界不补数。前端不计算性能模型，不用总体理想命中率判定SLO达标，100%参考需求不等于生产可达到。
- MA监控：GF规格×UUID，选规格即列出全部UUID，可展开图表；同UUID跨appid/P共享、不同UUID隔离。手动pre/now连续两个1小时文件，pre空缓存预热、仅now统计；每次任务独立，不自动采集或续接缓存。
- MA图表：按request_time的12个5分钟桶及整小时平均，称记录时间请求速率；实际未命中量为生产prompt_tokens−cached_tokens，与用户理想重算C不同。生产输入与实际未命中两张独立分布图，各有有效数/覆盖。无记录桶与字段无效桶的0/null不同，不能称GPU利用率/计算吞吐。
- MA对照：并排理想/真实使用同一Q请求集合及各自分母，保留R/E独立量、覆盖、输入计量差异和预热条件。真实可能高于有限预热理想，不自动解释为路由损失；处理顺序冲突、无预热、仅pre、空文件/全部坏行等应可区分。
- 前端只消费已发布成果，切页/图表不触发分析或回放；保留完整发布、固定版本、缓存、精确十进制整数、null不补零、UTC原值/北京时间展示。MA、用户和服务身份/缓存键分别管理，旧S0不能充当V2契约。
